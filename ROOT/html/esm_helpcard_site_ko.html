회사에 여러 지역에 여러 지점이 있는 경우 각 지점은 지역 아래에 별도의 사이트로 구성됩니다.

사이트는 사용자 섹션을 통해 AD 또는 CSV에서 가져오거나 ESM 디렉토리 아래에만 수동으로 추가할 수 있습니다. 사이트 삭제 또는 편집은 ESM 디렉토리에서만 가능합니다. 여기에서 사이트의 주소, 연락처 및 조직 역할과 같은 일반적인 세부 정보를 관리할 수 있습니다.

사이트 추가의 이점

  • 사이트별로 문제를 분리하고 식별하는 데 도움이 됩니다.
  • 사이트 기반 보고서 생성에 도움이 됩니다.

사이트 기반 조직 역할 추가의 이점

  • 사건 요청서 및 서비스 요청서에 대한 사이트 승인 권한을 더 쉽게 선택할 수 있습니다.
  • 중요한 알림 구성에서 사이트 권한을 반복하는 데 도움이 됩니다.
사이트별 관련 설정은 해당 서비스 데스크 인스턴스에서만 관리해야 합니다.

참고: 부서는 관련 설정에서 사용할 수 없습니다.

비활성 사이트는 다음 시나리오에서 활성 상태로 변경됩니다.

a. 성공적인 Active Directory 가져오기 후.
b. 사용자 및 자산의 CSV 가져오기.

비활성 사이트는 다음과 같은 경우 자동으로 활성화되지 않습니다.

a. 비활성 사이트에 대해 이메일 명령을 통해 요청서 생성.
b. API를 사용하여 비활성 사이트에 대한 요청서, 자산, 기술자 생성 및 편집

사이트 삭제

사용자, 자산, 부서, 예방 유지 관리 작업 및 관련 인시던트 템플릿과 같은 엔터티가 없는 사이트는 한 번에 삭제할 수 있습니다. 그러나 엔터티 연계가 있는 사이트는 삭제하기 전에 해당 엔터티를 다른 사이트에 다시 배정해야 합니다.

연계된 항목을 다른 사이트로 이동

사용자가 삭제하려는 사이트와 연계되어 있으면 사용자 연계를 다른 사이트로 이동하라는 팝업이 표시됩니다. 연계하려는 새 사이트에 사용자의 부서가 없으면 새 사이트 아래에 새 부서가 생성됩니다.

참고: 사이트 삭제를 위해서는 사용자 연계에 다른 사이트를 할당해야 합니다. 이 액션은 조직 관리자(Org Admin)만 수행할 수 있습니다. 사용자 연계를 다른 사이트로 이동하는 경우, 인스턴스 사용자 가져오기 기준에 따라, 사용자가 인스턴스 외부로 이동하거나 해당 인스턴스에 추가될 가능성이 있습니다.

특정 인스턴스 엔티티 이동

자산, PM 태스크, 요청서 템플릿, 참조 사이트, 인스턴스 담당자 가져오기 기준과 같은 특정 인스턴스 엔티티 이동은 인스턴스 담당자가 완료해야 합니다. 특정 인스턴스 엔터티가 있는 사이트가 삭제될 때마다 연계된 엔터티를 다른 사이트로 이동하라는 알림이 해당 인스턴스 담당자에게 전송됩니다. 모든 포털 관련 특정 엔터티 이동이 완료되면 사이트는 애플리케이션에서 제거되거나, 모듈과의 연계 여부에 따라 비활성 사이트 목록에 남습니다.
