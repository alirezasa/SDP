通过自定义触发器，可以使用脚本文件或者自定义Java类文件，执行需要的特定'动作'。在'添加新动作'的窗口中，指定动作的名称和动作的简要描述。从下拉列表中，选择执行该动作的时机。在匹配条件中，选定适当的条件和该条件的属性值。选择'动作类型'以及要触发的脚本文件。反选'停止处理后续动作' 将在该动作应用之后，继续执行后续的动作。

说明:

  • 请确保动作名称的唯一性，不会与已有的动作发生冲突。
  • 新的动作可以在变更被 '创建' , '编辑' 以及 '创建或编辑'时被执行。
  • 确保脚本文件/类文件存放于指定的位置。存放目录为： [SDP_Home]/integration/custom_scripts/
  • 默认情况下，'停止处理后续动作'被选中，因此，在动作执行之后，其后的动作不会被执行。
  • 可通过'编排动作s'，重新编排要执行动作的顺序。

示例的场景:

当一个紧急变更请求被提交后，需要为其配置紧急CAB，以便立即验证并审批该紧急变更。故在这里定义了紧急变更提交时要执行的新动作，通过自定义脚本来实现上述的要求。

 

技术员明细:

如果您选择执行类型为Java类，需要在要执行的脚本/类文件出，提供相应的类文件。如： "com.servicedeskplus.integration.ChangeActionImplementation"。

如果选择的执行类型为脚本，则需要执行脚本名称和相应的脚本文件的路径。如："py addApprovers.py"。

不管是脚本还是类文件，都支持指定变量。

如: py addApprovers.py $TITLE $TYPE $TEMPLATE

对于类：com.servicedeskplus.integration.ChangeActionImplementation $TITLE $TYPE $TEMPLATE

支持的其它参数:

$COMPLETE_JSON_FILE ---> 完整的请求对象将被保存为一个 JSON 文件，文件路径将作为字符串对象提供。如果执行时机为：'当变更被编辑时', 还会将 DIFF_JSON (旧变更数据与新变更数据的差异) 也保存到一个 JSON 文件。

JSON 文件路径：(SDP_Home\integration\custom_scripts\change\12_1426143538036.json).

触发器应用的输入数据:

{
INPUT_DATA :
{
"login_name" : "logged in user's name",
"entity" : "module name: here change",
"entity_diff_data" : "difference between the old change data and new change data",
"entity_data" : "GET change API response"
}
}
