Custom triggers enable you to automate the process workflow using customized actions based on user input. Define conditions to be met and actions to be executed on records that satisfy the specified conditions.

On this page, you can create various custom triggers. You can also create trigger groups to organize and manage the various custom triggers.

First create a Trigger Group and Save. Then, hover over it and create a new trigger rule.

  • Click Add Trigger
  • Name and Description: Provide a name and description for the trigger rule.
  • Execute on actions:
    Request

    You can apply the custom triggers for all requests that are Created, Edited, Deleted Permanently, or Moved to trash.

    Note

    You can apply the custom triggers for all notes that are Created, Edited, or Deleted Permanently.

    Notification

    You can apply the custom triggers for all notifications that are Sent by User, Deleted Permanently, Forward, Sent by Technician, or System Notifications

    Approval Level

    You can apply the custom triggers for all approval levels that are Created, Level Approved, or Level Rejected

    Approval

    You can apply the custom triggers for all approvals that are Created, Approval Approved, Approval Rejected, Approval Sent, or Deleted Permanently.

  • Execute during: Choose the trigger execution time window from Any Time, Within Operational Hours, or Outside Operational Hours
  • Cascade Execution: Choose the order of trigger execution from Execute next rule, Skip remaining rules in this group, or Skip remaining rules across all groups
  • Condition: Choose whether to apply specific conditions, custom conditions, or no conditions to the incoming request.
    • Apply conditions based on criteria: Choose from condition-criteria from the drop-downs
    • Apply conditions using custom function: Either choose an already created custom function or create a new custom function to process the conditions.
    • Apply no condition: This will apply the custom trigger on all incoming requests.
  • If the trigger is set to execute when a request is edited and based on conditions, you can choose to execute the trigger:
    • Every time the request is edited.
    • Only when the fields configured in the conditions are edited.
  • Action: After defining the criteria-conditions, you can configure actions.
    • Execute custom actions:
      Request

      You can choose from Notification Action, Custom Function, Execute Script, Execute Class, Webhook, If-If and If-Else

      Note, Notification, Approval Level and Approval

      You can choose from Notification Action, Custom Function, and Execute Script.

NOTES:

Choosing Deleted Permanently enables you to trigger notifications to specific users when the request is deleted from trash

Under Execute custom actions, you will be able to choose either Custom Functions or Execute Script at any given point. You cannot configure both actions.

For Notifications, the System Notification event will apply only default notifications configured in the application.

List View Actions

From the list view of custom triggers, you can organize the trigger rules and rule groups, configure cascade execution, and move rules across groups.
