カスタムトリガ―で、スクリプトファイル、カスタムクラスファイル、カスタム関数を使用して、お好みの［アクション］を自動的にトリガーすることができます。［新規アクションの追加］ウィンドウ内で、新規アクションに名称と説明を入力します。「アクションタイプ」 と「実行するスクリプトファイル」を選択します。［後続アクションの処理を停止します］のチェックボックスを無効にすると、変更にアクションのルールが適用された後も、後続のアクションが実行されます。

注意:

  • 既存の「アクション名」と競合しないよう、「新規アクション」の名前は一意なものかを確認してください。
  • 新規アクションは変更が ［作成］、［編集］と［作成か編集］された際に、実行されます。
  • スクリプトファイル / クラスファイルは指定した場所にのみ保存されます。これらのファイルは、以下のディレクトリに保存されます。: ＜インストールディレクトリ＞\ManageEngine\ServiceDesk\integrationin\custom_scripts
  • デフォルトでは、 ［後続アクションの処理を停止］は常に有効で、アクションはアクションルール順に実行されます。
  • ［アクションの編成］では、アクションを実行する順番を再編成することができます。

簡易例：

緊急な変更リクエストが起票された際、変更リクエストを早急に確認、承認するために緊急のCABを構成する必要があります。緊急のリクエストが起票された際にカスタムスクリプトが実行されるために新規アクションを設定します。

技術的な詳細：

「アクションを実行」内で、クラス、スクリプト、カスタム関数のどれを実行したいかを選択し、以下を参考に同じように設定します。

  • クラスの実行：実行するExecutorクラスを入力します。
    例）com.servicedeskplus.integration.ChangeActionImplementation
  • スクリプトを実行：実行したいスクリプトを含むテキストファイル名を入力します。
    例）AddApprovers.txt
  • カスタム関数を実行：カスタム関数を実行することで、ServiceDesk Plusやその他外部のアプリケーションのデータを操作することができます。お好みのカスタム関数を選択するか、新規に追加します。カスタム関数では、changeObjとcontextの引数がサポートされています。

注意:

  1. スクリプト/クラスでは、引数として「 py addApprovers.py $TITLE $TYPE $TEMPLATE」のような、すべてのAPIパラメーターを渡すことができます。クラスでは「com.servicedeskplus.integration.ChangeActionImplementation、$TITLE $TYPE、$TEMPLATE」のような引数を渡すことができます。
  2. changeObjとcontextはカスタム関数でサポートされている引数です。

スクリプトでサポートされているその他のパラメーター：

$COMPLETE_V3_JSON_JILE：Complete Request ObjectがJSONファイルに保存され、そのファイルパスがString型として渡されます。［変更が編集されたとき］を選択した場合、その後 DIFF_JSON (変更前のデータと新規に変更されたデータ間での差異) も JSONファイルに保存されます。

$HELPDESK_ID ： ポータルのIDです。このIDは、新しいURLパラメーター「PORTALID」に対して、ServiceDesk Plus全てのAPIコールへの値として渡す必要があります。これは、ESM設定を有効化している場合にのみ利用することができます。

JSONファイルパス：＜インストールディレクトリ＞\ManageEngine\ServiceDesk\integration\custom_scripts\change\12_1426143538036.json

入力データサンプル：

{
INPUT_DATA :
{
"login_name" : "logged in user's name",
"entity" : "module name: here change",
"entity_diff_data" : "difference between the old change data and new change data",
"entity_data" : "GET change API response"
}
}
