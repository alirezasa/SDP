A change template contains a canvas, a header, and various fields.

Header:Consists of the template name and workflow, along with the Undo and Redo buttons.

Canvas:Is the visual builder into which you can drag various fields and create the workflow.

Fields:Any change additional fields configured in the application and the fields removed from the canvas are listed in this section.

Duplicating Change Templates: Instead of creating individual forms for each Change Template, click Duplicate Template to create duplicate templates for similar change requests. Duplicating a template retains the fields in the canvas and renames the new template as Copy of (Template Name).

To create a change template,

  • Click Add Change Template.
  • Provide a template Name and Description and select the Workflow for the template to follow.
  • Use the checkboxes displayed on the top to mark emergency or default templates
    • .
  • Customize the fields in the template form, add and group fields into sections, and customize the template layout.
  • Configure Change Roles.
  • Under Field & Form rules, configure the On Form Load, On Field Change, and On Form Submit rules.
  • Click Save.

Use the Search icon to search for your preferred change template.

Using Actions icon, you can edit, disable, delete, or mark a change template as default. You cannot, however, disable or delete the default template.

Click the Workflow icon next to the selected change to preview the assigned workflow status.

Note:
  • If a change template is deleted while being used in changes, the template will be disabled. You can restore an inactive change template by editing it.
  • When you set a default template, all new change templates will contain the default configurations.
  • Deleting the default template from the Change Template List View is not allowed. Instead, you can set another template as the default template and then delete the previous default template.
  • While creating a change request, the fields in the form will be populated based on the default template.
  • If you have added or deleted a user from a role, the modifications done will reflect only in the forthcoming change requests. Deleting a role will delete the role from the change request, which does not have any users assigned to it.
  • The maximum number of roles that can be added is 12.
  • The change owner, and change requester roles can't be added or edited under Change Roles.
  • SharedRole allows you to share a change with your technicians. You can share the change with specific technicians or all technicians by selecting $AllTechnician.
  • Change requests shared with all technicians will not appear under My Changes in the list view.
  • Technicians will be notified only when they are individually selected for SharedRole.
  • You can add a new role in the Change Roles page under Admin > Customization > Change Roles and selecting Add. The added role will be shown in the Change Roles under Admin >Templates and Forms > Change Template, after refreshing the page.
Field and form Rules:

With Field & Form Rules, you can define rules that can be executed on a change form. Field and form rules are executed after a change form is loaded, submitted, and on field change. Field & Form Rules are not executed on the server side but on the client side. Rules can be disabled or enabled.

Events supported in Field & Form Rules:

On Form Load: Rules are executed each time the change form is loaded.

On Field Change: Rules are executed when the field value changes. Rule will be applied when a field value mentioned in the rule is changed.

Note:
  • The rules defined should contain at least one action to be executed.
  • The actions will be executed after checking the criteria. If no criteria is set, the actions will be executed in the organized order.

On Form Submit: Rules are executed when the change form is submitted. Execute Script is the only action allowed for this event. Rules defined for this event should contain a valid script. Script will be executed after checking the set criteria, and if no criteria is defined, the script will be executed directly.

Applicable To Users: Rules can be applied to all users or technicians except ChangeOwner, ChangeManager, or SDChangeManager.

Rule Execution: Rules can be executed on creating a new change request or on editing an existing change request or both.

Copying Rules To Another Template: One or more rules can be copied from one template to another using Copy rule in the actions menu. If no criteria is set for certain rules, then such rules will not be copied.

Removing Fields from Change Form: Removing fields from the template would automatically remove fields from the rules defined for that template. If the fields are deleted and no criteria is set for certain rules, then such rules will be deleted.

Actions supported in Field & Form Rules:

  • Show Fields
  • Hide Fields
  • Enable Fields
  • Disable Fields
  • Mandate Fields: Makes given fields mandatory in the change form. User will not be able to submit the form without filling value for these fields.
  • Non-Mandate Fields: Removes mandatory property of given fields in the change form on which this action is applied. Thus user can submit form without filling value for these fields.
  • Execute Script: Executes script in the change form. Script should be a valid JavaScript code. Otherwise script won't be executed. Some methods are supported as default methods in script execution. For example to hide category and level fields you can call below method with an array of fields as. eg: $CS.hideField(["CATEGORY","LEVEL"]);
