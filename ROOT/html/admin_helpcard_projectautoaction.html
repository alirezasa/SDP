Use Project Trigger to automatically trigger any 'Action' on a project using a script file or a custom function.

To create a new custom trigger for projects,

  • Click New Action.
  • Enter a name and description for the action and select when the action must be executed.
  • Select the Action Type (Custom Functions/Scripts) and point to the corresponding script file which needs to be triggered.
  • Set Criteria under which the action must be executed on project. You can add multiple criterions by clicking on the + icon. Switch between AND and OR operators between the criterions as per your requirement.
  • Deselecting 'Stop processing subsequent actions' checkbox will execute successive action even after an action rule is applied on a project .

Note:

  • Make sure that you enter a unique name for the 'New Action', so that the name doesn't clash with existing 'Action' names.
  • Ensure that the text file is stored only in [SDP_Home]/integration/custom_scripts/executor_files directory and the script file is stored only in [SDP_Home]/integration/custom_scripts/
  • By default, 'Stop processing subsequent actions' is always enabled and the actions will be executed as per the 'Action rule order'.
  • 'Organize Actions' in the list view allows you to rearrange the order in which the actions are executed.

TECHNICAL DETAILS:

Under Perform Action, choose whether you want to execute a script, or a custom function and configure the same using the following pointers:

  • Script: Specify the name of the text file containing the script content . For example, AddComments.txt
  • Custom Function: By executing custom functions, you can manipulate data in ServiceDesk Plus and other external applications. Choose the required custom function or add a new one.
  • Supported Return Operations: UPDATE_PROJECT & ADD_COMMENTS

Note :

  • In a script, you can pass API parameters as arguments, such as py addComments.py $TITLE $TYPE.
  • projectObj and context are the arguments supported in custom functions.

Other Parameters Supported in Script:

$COMPLETE_V3_JSON_FILE ---> Complete Request Object will be saved to a JSON file and the file path will be passed as String Object. If the Operation is 'When a Project is edited', then DIFF_JSON (difference between the old project data and new project data) will also be saved to a JSON file.

$HELPDESK_ID ---> The ID of the portal. This ID needs to be passed as the value to all SDP API calls, against new URL parameter 'PORTALID'. This is applicable only for ESM enabled setups.

JSON File Path : (SDP_Home\integration\custom_scripts\project\12_1426143538036.json).
