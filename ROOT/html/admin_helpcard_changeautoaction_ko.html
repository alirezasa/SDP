사용자 정의 트리거를 사용하면 스크립트 파일이나 사용자 정의 클래스 파일 또는 사용자 정의 함수를 사용하여 필요한 '액션'을 자동으로 트리거할 수 있습니다. '새 액션' 창에서 새 액션의 이름과 설명을 입력합니다. 드롭다운 목록에서 액션을 실행해야 하는 조건 기준을 선택합니다. '기준' 필드, 관련 조건 및 필드 값을 설정합니다. '액션 유형'을 선택하고 해당 스크립트 파일이나 클래스 파일 또는 트리거되어야 하는 사용자 정의 함수를 선택합니다. '다음 액션 처리 중지' 확인란의 선택을 취소하면 한 변경에 액션 규칙이 적용된 후에도 연속 액션이 실행됩니다.

참고 사항:

  • 이름이 기존 '액션' 이름과 충돌하지 않도록 '새 액션'에 유일한 이름을 입력해야 합니다.
  • 스크립트/class 파일이 지정된 위치에만 저장되어 있는지 확인합니다. 다음 디렉토리에 저장합니다. [SDP_Home]/integration/custom_scripts/
  • 기본적으로 '다음 액션 처리 중지'는 항상 활성화되어 있으며 작업은 '액션 규칙 순서'에 따라 실행됩니다.
  • '액션 구성'을 사용하면 액션이 실행되는 순서를 다시 정렬할 수 있습니다.

샘플 시나리오:

긴급 변경 요청이 발생하면 즉시 변경 요청을 확인하고 승인할 수 있도록 긴급 CAB를 구성해야 합니다. 여기에서 긴급 변경 요청이 발생할 때 사용자 정의 스크립트 또는 사용자 정의 함수를 실행하도록 새 액션을 구성할 수 있습니다.

기술적 상세 정보:

액션 수행에서 클래스, 스크립트 또는 사용자 정의 함수를 실행할지 여부를 선택하고, 다음 포인터를 사용하여 구성합니다.

  • Class: Executor 클래스를 지정합니다. 예: com.servicedeskplus.integration.ChangeActionImplementation.
  • Script: 스크립트 실행 내용이 포함된 텍스트 파일의 이름을 지정합니다. 예: AddApprovers.txt.
  • Custom Function: 사용자 정의 함수를 실행하여 ServiceDesk Plus 및 기타 외부 응용 프로그램에서 데이터를 조작할 수 있습니다. 필요한 사용자 정의 함수를 선택하거나 새 함수를 추가하십시오. changeObj 및 context는 사용자 지정 함수에서 지원되는 인수입니다.

참고 사항::

  1. 스크립트나 클래스에서 모든 API 매개변수를 인수로 전달할 수 있습니다(예: py addApprovers.py $TITLE $TYPE $TEMPLATE). 클래스에서 com.servicedeskplus.integration.ChangeActionImplementation $TITLE $TYPE $TEMPLATE를 전달할 수 있습니다.
  2. changeObj 및 컨텍스트는 사용자 정의 함수에서 지원되는 인수입니다.

스크립트에서 지원되는 기타 매개변수:

$COMPLETE_V3_JSON_FILE ---> 전체 요청 개체는 JSON 파일에 저장되고 파일 경로는 문자열 개체로 전달됩니다. 오퍼레이션이 '변경 사항을 편집할 때'인 경우 DIFF_JSON(이전 변경 데이터와 새 변경 데이터의 차이)도 JSON 파일에 저장됩니다.

$HELPDESK_ID ---> 해당 포털의 ID. 이 ID는 새 URL 매개변수 'PORTALID'에 대해 모든 SDP API 호출에 해당 값으로 전달되어야 합니다. 이는 ESM 활성화 설정에만 적용됩니다.
