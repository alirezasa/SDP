요청서 데이터 삭제 예약

데이터 삭제를 사용하면 시스템 메모리에서 불필요하게 공간을 차지하는 오래된 요청서 데이터를 삭제할 수 있습니다. 설정된 기준과 일치하는 활성 또는 보관된 요청서를 삭제하려면 이 옵션을 활성화합니다.

  1. 예를 들어 1년 전에 생성된 완료된 모든 요청을 삭제하는 기준을 설정할 수 있습니다. 이렇게 하려면 규칙 섹션에서 다음 값을 선택하십시오; 요청서 상태가 완료 상태 AND(이고) 만든 날짜가 1년 이전.

  2. 예약된 삭제에서 특정 요청서들을 제외하려면 삭제 예외 허용 옵션을 활성화하고 해당 기준을 설정하면 됩니다.

  3. 예를 들어, 예약된 데이터 삭제에서 관리 부서의 요청서가 삭제되지 않도록 제외할 수 있습니다. 그렇게 하려면 규칙 섹션에서 다음 값을 선택합니다. Column Name - Department, Criteria - is, Value - Administration( 이름 - 부서, 기준 - is, 값 - 관리). 더하기 아이콘을 클릭하여 여러 규칙을 추가할 수 있습니다. 기준을 설정했으면 시간과 분을 지정하여 데이터 삭제 일정을 설정하고 저장합니다.

 

요청서 데이터 보관 예약

데이터 보관은 모든 요청서를 정기적으로 백업하는 프로세스로 본 애플리케이션의 성능을 크게 향상시킵니다. 이 옵션을 활성화하면 설정된 기준과 일치하는 요청서들을 보관할 수 있습니다.

  1. 예를 들어 기준을 설정하여 1년 전에 생성된 모든 해결됨/종료된 요청서들을 보관할 수 있습니다. 이렇게 하려면 규칙 섹션에서 다음 값을 선택하십시오. [요청 상태가 Resolved/Closed, AND Created Date, is before 1 year] (해결됨/종료됨 AND 생성일이 1년 이전). 기준을 설정한 후 저장을 클릭합니다.

  2. 설정된 기준과 일치하는 일부 요청서들을 보관하지 않으려면 보관 예외 허용을 선택하고 요청서 보관 제외 기준을 설정하면 됩니다.

  3. 기준과 예외를 구성했으면 시간과 분을 지정하여 요청서 보관 시간을 예약합니다.

 

참고:

  1. 보관된 요청서는 수정할 수 없지만 삭제할 수 있습니다.

  2. 보관된 요청서는 현재의 활성 요청서 목록 아래에 나열되지 않습니다.

  3. 보관된 요청에 대한 보고서를 보거나 검색하거나 생성하려면 요청서 모듈의 보관된 요청서 필터로 이동하십시오.

  4. 이미 보관된 요청서에 대한 모든 회신은 새 요청서로 추가됩니다.

  5. 데이터 보관과 데이터 삭제가 모두 활성화된 경우 데이터 삭제가 먼저 실행됩니다.

  6. 데이터 삭제 및 보관 일정은 동일합니다. 보관 일정을 변경하면 삭제에도 적용됩니다.
