The service requests created in the application can be assigned with specific SLAs to set the response date and due by date for the requests.

The Add New SLA form has three blocks of information:

  • SLA Details

    • Enter a unique name and description for your SLA.

  • SLA Rules

    • Set the first response time and resolution time for the request. You can define if the SLA must be applied irrespective of operational hours, holidays and weekends.

  • Escalations

    • Select an escalation level and the technicians to notify, if the first response time/resolution time limit is exceeded.

    • To escalate a request before the SLA is violated, choose Escalate Before and set the time of escalation.

    • Click Escalate After to escalate after the violation.

    • Click Actions to select the technician, group, priority and level of the request after escalation. For example, you can assign the request to a group that has specific technicians to supervise the request.

Note: In the group drop down, the default support groups will be listed. Similarly in the technicians drop down, technicians who are not associated to any sites will be listed.

You can configure different sets of actions for all the 4 escalation levels associated with the resolution time.

Operational Level Agreement

Operational Level Agreements (OLA) define how various IT groups within a company plan to deliver a service. You can configure OLAs for every SLA to decide how the SLA can be achieved by the internal groups working on the request.

  • Fill in the relevant information:

    • Group Name - Enter the group(s) which will handle the request.

    • OLA Time - Set the time within which the selected groups must finish working on the request.

    • Description - Add a short description, if needed.

  • To add configure different OLA times for different groups, click (+) button.

Click Save or Save and Add New.
