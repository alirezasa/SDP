Business Rules enable you to organize all the incoming requests and perform actions such as delivering them to groups, assigning status and other request parameters. The business rule can be applied to a request when it is created (or received), edited or both. Notification can also be sent to the technicians, once the Business Rule is executed. The Business Rules are site specific. Hence to view the Business Rules of a site, select the site from the Business Rules for combo box.

Note:

    • The administrator has the privilege to set the business rules for all the site whereas, the Site Admin has the privilege to set and view the business rules for the sites associated to him.

    • If the sites are not configured in Admin -Sites, then the Business Rules for combo box will not appear. 

    • If the Business Rules of a particular site refers to another site's settings, then during the site change, a pop-up denoting the selected site's refer site will be displayed.If the Business Rules configured for the Site to be deleted is being referred by one or more Site(s), then during the Site deletion process, the Site(s) to be deleted will be listed along with the Business Rules that they refer. You can either choose the refer Site's settings to refer default settings or change to any other Site's settings that you require. 

Add New Business Rule
Select the site from the Business Rules for combo box. If no site is selected then the business rule gets added under Default Settings. Click Add New Business Rule link on the right hand side corner of the Business Rule List view.
 
The Add Business Rule form consists of three major blocks to be configured, namely Business Rule Details, Criteria and Actions and Notification.  

Rule Name uniquely identifies the rule. It is a mandatory field.
The Site selected in Business Rules for combo box is displayed in a non editable field.
Enter the content to describe the business rule in detail in the Description text box.

The Business Rule can be executed on a request when it is created via web form (or received via mail), edited or both by choosing the options from Execute when a request is drop-down list. By default, 'Created' option is selected.

Disable Business Rule: Select this option to disable a Business rule. By default, this option is unchecked. On disabling a Business Rule, the rule will not get executed on any new or edited request.

Turn on Cascade Execution: By default, the execution of the business rule will stop once a rule is applied on a request. On selecting Turn on Cascade Execution check box, execution of successive business rules will continue (as per the business rule order) even after a business rule is applied on a request.

Override request values with Business Rule values: Enabling this option will override the values in the request with values mentioned in the Business Rule.
Example: If the Priority in a request is set to 'High' and the Actions Set in the business rule is 'Set Priority to Low', then the priority is automatically set to 'Low' on executing the business rule.

Note: To perform bulk actions on business rules such as, enable/disable business rules, Turn on/off Cascade execution and delete, select the check box beside the business rule and click Actions drop down button in Business Rules list view page.

 
Criteria and Actions is where you can define rules by matching criteria for the incoming incident requests. The actions performed on the request can be achieved automatically without manual intervention.

From the Define Rule block, select the specific criteria and a condition from the drop-down list. Click Choose button to add the specific values. Now click Add to Rules. The rule that you just defined is added in the table below. You can choose to match all the criteria set or match any of them by choosing the corresponding radio button.

Now set the appropriate action that need to be performed on the requests that match the above rule criteria that you have added.

Select the action item to be performed on the request from the Choose Action drop-down menu. Select the values to be associated to the request by clicking Choose button. Click Add. The added action(s) get added to the Actions table.

Once the Incident template is added in this Actions table, it will be applied on a request, created using the Default Request Template only. The Request template will be applied first, followed by the other actions.

 

Negate Create/Edit Operation: This action lets you to Negate (discard/revert) an operation (Create/Edit Request). For instance, using this you can stop a request that matches the configured business rules criteria from being created. You can also stop a request from being updated/edited. Once this action is performed, all the applied rules will be discarded.

You can also give a reason for performing the Negate Operation by clicking on the "Choose" button. The reason will be shown when a request is negated.
This option cannot co-exist with any other action for a rule. Once this action is selected, option to add any further actions will be removed. Cascade Business Rule option will be removed as well.

Execute Script: This action lets you to execute custom actions using script file for incoming/edited requests. It helps in performing some additional actions that are not available in the default actions menu of the Business Rule. Scripts can be executed to update/negate the requests.

Note: 'Execute Script' action will be executed first followed by the other actions.

Parameter supported :

$COMPLETE_V3_JSON_FILE : The complete request objects will be saved in the JSON file. $COMPLETE_V3_JSON_FILE string will be replaced with the temporary JSON file path. The same JSON file must be returned to the server with the Output.

Temporary JSON file path: [SDP_Home]/integration/custom_scripts/requests/1_1234567.json

Sample script command: cmd /c updateRequest.bat $COMPLETE_V3_JSON_FILE

Custom actions such as UPDATE/NEGATE is supported using the script file.

Execute Custom Function: By executing custom functions, you can manipulate data in ServiceDesk Plus and other external applications. requestObj and context are the arguments supported in custom functions. Choose the required custom function or add a new one.

Notification is where you can send Email and SMS notification to technicians once a business rule is applied. To enable Email notification,

Select the check box beside Email to enable email notification to the technicians. The technicians can be selected by clicking Add button. All the technicians corresponding to the selected site is displayed. You can also edit the Email Template by clicking the edit template link.

Similarly, notification can also be sent by SMS to the technicians. The notification is configured in the same manner as Email.

Note: The Mail Server Settings should be configured to receive the Notification.

Click the Save button to save the Business Rule and return to the list view. Click the Save and Add New button to save the Business Rule and add another Business Rule.

Organizing Business Rules
To organize the Business Rules, click the Organize Business Rules link and in the pop-up, select the business rule and click Move up or Move Down button. It decides the order in which the rule is applied on the incoming request.
