On-Premises to Cloud Migration

On this page, you can migrate the Admin module data from ServiceDesk Plus On-Premises to ServiceDesk Plus Cloud. Before you start, make sure you read the Terms and Services to find the list of entities that will be migrated automatically and those to be migrated manually.

ServiceDesk Plus uses OAuth 2.0 to communicate between On-Premises and Cloud servers. OAuth 2.0 is an authentication method that provides delegated access to a protected resource using web tokens instead of passwords. Click here to learn more.


Once you have manually migrated the required entities, you can initiate automatic migration by filling in the migration form using the following pointers:

Field Explanation
ServiceDesk Plus Cloud Data Center Choose the Data Center to identify the Domain URL of ServiceDesk Plus Cloud.
Domain URL The Domain URL will be auto populated based on the Data Center.
Client ID and Client Secret Provide Client ID and Client Secret generated in the authorization server. Learn how to do this here
Redirect URL Redirect URL provided must be copied to the authorization server for generating the Client ID and the Client Secret.
Mode Choose the mode of migration for service desk data. Note that this does not apply to admin data, assets, and solutions.
  • Trial Mode - Data created within the last 30 days will be migrated.
  • Full Mode - Select the range for the data to be migrated. Data created within 1 year can be migrated in this mode. You can extend this range up to 5 years. Click here to learn more.

When you click Next, a window will pop up, where you can give your consent after signing in to your ServiceDesk Plus Cloud account. Select the ServiceDesk Plus Cloud instance to which the data needs to be migrated. Select the entities to migrate and click Move Data. A report showing the migration progress will be displayed.

Once the admin data is migrated, the migration will be paused so that you can manually migrate admin entities that are not migrated by system. Click Resume to migrate module data.

When the migration process is underway, you can Pause/Resume or Cancel Migration using the respective buttons. You can select and rerun the migration for failed entities using the Rerun option shown in the banner after migration is complete. You can also rerun migration after being paused by the system.

Post migration, click Go to ServiceDesk Plus Cloud to access the cloud instance.

To view the status of the data added or updated in ServiceDesk Plus Cloud, go to Setup >> Import Data >> Import History.

To know more about the prerequisites for migrating data from On-Premises to Cloud, refer to the admin guide.

 

Note

  • If the license is not enabled for any entity/module in On-Premise, the respective entity/module data will not be migrated.
  • Inline images, attachments, sub-entities (eg: task template, resources, and questions under request template) will be migrated along with the entity data.
  • Inactive admin entities will also be imported without any error.
  • Data related to features that are not available in ServiceDesk Plus Cloud will not be migrated.
  • Avoid database operations while migrating the data from On-Premises to Cloud. This might result in migration failure.
  • All the data to be migrated will be zipped and placed in zip files under the 'Conversion' folder and will be deleted on a successful import.
  • Instance to Instance migration is possible. i.e data from one particular ServiceDesk plus On-premises instance can be migrated to the ServiceDesk Plus Cloud instance selected in the form.
  • Migration cannot be started in two instances at the same time. Only one migration will be handled at one time.
  • No maximum limit for adding attachments but the total attachment size of one entity(all attachments included) must not exceed 48 MB. Attachments greater than 48 MB will not be migrated.
  • License check, technician count, and additional fields count need to be verified manually in Cloud before starting the migration.
