セルフサービスポータル設定

セルフサービスポータル設定では、セルフサービスポータルに表示するフィールドを選択することができます。設定には、デフォルト通貨、表示言語、週の始まりの曜日、公開URLの設定、ヘッダーのロゴ画像のカスタマイズなども含まれます。

オプション はい いいえ
新規リクエストフォームの依頼者選択一覧に技術担当者名を含める?[デフォルトは"はい"] すべての技術担当者を依頼者一覧に表示できます。 一部の技術担当者を依頼者一覧に表示できます。
リクエストをプロジェクトと関連付けることを依頼者に許可しますか?[デフォルトは"いいえ"] 依頼者はリクエストの該当プロジェクトとの関連付けが可能になるので、プロジェクトとリクエストのマッピングが実行し易くなります。 権限がない依頼者は、リクエストとプロジェクトとの関連付けは実行できません。

依頼者自身がクローズリクエストを再オープン（「Open」ステータスに変更）することを許可する?[デフォルトは"いいえ"]

 依頼者自身がクローズしたリクエストを再オープンし、編集できます。リクエストのステータスが「Closed」、もしくは「Resolved」に変更すると、再オープンタブがリクエスト表示ページに表示されます。 権限がない依頼者は、自身がクローズしたリクエストを再オープンできません。
「Resolved」（解決済み）ステータスのリクエストを依頼者自身が「Closed」（クローズ）ステータスに変更することを許可する? [デフォルトは"いいえ"] 依頼者は、自身が解決したリクエストをクローズすることができます。リクエストのステータスが「Resolved」に変更すると、クローズタブがリクエスト表示ページに表示されます。 権限がない依頼者は、自身が解決したリクエストをクローズできません。
依頼者から返信を受け取ったら、OnHold（保留）ステータスのリクエストをOpen（オープン）に変更する?[デフォルトは"いいえ"] 依頼者がメール/ポータルから返信した場合、「Onhold」のリクエストをオープンします。 依頼者がメール/ポータルから返信しても、「Onhold」リクエストはオープンされません。
  • 依頼者が「Closed」ステータスのリクエストにメール/ポータルから返信した場合、次のオペレーションを実行する： 対応済みリクエストへの返信に対するオペレーションを次のオプションから選択します;
    • リクエストを常に再オープン（Open）する。
    • リクエストのクローズから指定日以内なら同じリクエストとして再オープンする。それ以降は、新規リクエストとして追加。
    • 返信をリクエスト履歴に追加して、技術担当者に通知。リクエストのステータスは変更しない。
    • 新規リクエストと「OnHold」（保留）ステータスのリクエストに依頼者からの返信があった場合、リクエストステータスをオープン（Open）に変更する


  • 依頼者に「承認」タブを表示する(デフォルトは"有効"）；「承認」タブは、リクエストの依頼者とリクエストの承認者に表示されます。依頼者に「承認」タブを表示させたくない場合、この機能を無効にします。
    依頼者が、リクエストの承認ステータスや進捗状況を確認する必要があるかもしれません。このような場合、依頼者にリクエストの承認状況を表示することが可能です。承認タブには、承認者のメールアドレスや、承認を依頼した日時、リクエストのステータス（承認/承認待ち/却下）、承認者が返信した日時、承認者によるコメントなどが表示されます。承認タブでは、ほかにも、リクエストの依頼者や、リクエストの承認者も表示されます。

  • 依頼者情報：セルフサービスポータルで、依頼者によるプロフィールの編集を許可したり、依頼者に自分のプロフィールを確認できるよう許可できます。
    • 「私の情報」の編集:依頼者は、自身のプロフィールを編集できます。
    • 「私の情報」の表示:依頼者は、自身のプロフィールを表示できます。

  • 依頼者所有資産のみをセルフサービスポータルに表示する; デフォルトでは、システム管理者によって設定されたワークステーションがセルフサービスポータルの新規リクエストフォームにリストされます。依頼者に関連付けられているワークステーション情報のみをフォームに表示させたい場合は、依頼者所有資産のみをセルフサービスポータルに表示チェックボックスを有効にします。
オプション はい いいえ
依頼者にDefault request(新規リクエスト）テンプレートを表示しない[デフォルトは"いいえ"] 依頼者には、Default Request（新規リクエスト)テンプレートは表示されません。 Default Request（新規リクエスト）テンプレートがすべての依頼者に表示され、利用可能となります。
新規インシデントリクエスト作成中に依頼者にサジェストを表示する? [デフォルトは"はい"] 新規インシデントリクエストが作成される際、自動的に解決サジェストが依頼者に表示されます。 新規インシデントリクエストが作成される際、依頼者にサジェストは表示されません。
リクエストのステータス変更コメントの追加は必須にする[デフォルトは"いいえ"] リクエストステータス変更の際のコメント入力は必須となります。

リクエストステータス変更の際のコメント入力は任意となります。

一般設定:

  • 通貨:テキストフィールドに、デフォルト通貨を入力します。指定した通貨は、費用を計算する際に使用されます。デフォルトの設定通貨はUSドルです。

  • 通貨文字:該当する通貨の文字が表示されます。デフォルトは、$です。

  • 表示言語を選択する:デフォルトでは、ブラウザーのデフォルト言語が表示されます。ServiceDesk Plusでは、複数言語の表示をサポートしています。ドロップダウンメニューから、アプリケーション上で表示するデフォルト言語を設定することができます。

  • 週の始まりの曜日を選択する:ドロップダウンメニューから週の始まりの曜日を選択して、カレンダーのカスタマイズを行います。すべてのカレンダー表示で、選択した週の始まりの曜日の変更が適用されます。デフォルトの週の始まりは、日曜日です。

オプション はい いいえ
リクエスト情報ページにサイト情報を表示する?[デフォルトは"はい"] リクエスト表示ページに、サイトの情報（名称、住所、連絡先）を表示します。リクエストの表示ページのサイトフィールド横に"サイト情報の表示"アイコンが表示されるので、そのアイコンをクリックすると表示できます。 リクエスト表示ページから"サイト情報の表示"アイコンを削除します。
インシデントとサービス要求テンプレートをまとめて表示する[デフォルトは"はい"] インシデントとサービス要求テンプレートを結合します。インシデントとサービス要求のテンプレートがグループ化されて、新規リクエストドロップダウンに表示されます。 インシデントとサービス要求テンプレートを結合して、「新規リクエスト」ドロップダウンに表示しません。
Active Directory(AD)からユーザーをインポートしていなくても、ユーザーを動的に追加する?[デフォルトは"はい"] ServiceDesk Plusにユーザー情報を登録していなくても、Active Directoryからユーザーをインポートする機能を利用していると、Active Directory認証を利用してアプリケーションにログインできます。この機能を利用すると、エンドユーザーに自動でアプリケーションへのログイン権限を付与することができます。 ユーザーがアプリケーションにインポートされていない場合、ユーザーは動的に追加されません。
新規ユーザーからリクエストメールを受信したとき、そのユーザーにServiceDesk Plusのログインアカウントを自動作成する?[デフォルトは"はい"] 依頼者登録していないユーザーからメールが届くと、自動的にユーザーにログイン権限を付与します。 リクエストメールから未登録依頼者へのログイン権限を作成しません。
メールアドレスを識別子にしてユーザー情報を上書きする?[デフォルトは"はい"] Active Directory、CSV、LDAPからユーザー情報をインポートする際、既存のユーザー情報は、ユーザー名とドメインの組み合わせ、または、メールアドレスを条件に上書きされます。 メールアドレスを識別子にしてユーザー情報を上書きしません。
ローカル認証でのログインを許可する?[デフォルトは"はい"] ユーザーにローカル認証でのログインを許可します。 ユーザーはローカル認証ベースのログインができません。
未登録のメールアドレスからのメールを受信する?[デフォルトは"はい"] ServiceDesk Plusに未登録のメールアドレスからのメールをリクエストとして受信します。 未登録のメールアドレスからのメールを拒否します。
技術担当者にインシデントの「簡易作成」フォームを表示する?[デフォルトは"はい"] 技術担当者のホームに、簡易作成 - 新規インシデントを表示します。 技術担当者のホームに、簡易作成 - 新規インシデントを表示しません。
メール経由でリクエストが作成された場合、依頼者に割り当てられている資産を自動的にリクエストに関連付ける?[デフォルトは"はい"] ServiceDesk Plusでは、依頼者に対して複数のワークステーションを関連付けることが可能です。依頼者がメールでリクエストを追加すると、ユーザーに最初に紐付けられたワークステーションがリクエスト情報ページに表示されます。 メール経由でリクエストが作成されても、資産を自動的にリクエストに関連づけません。
ソリューション承認者による自己承認を許可する?[デフォルトは"はい"] ソリューション承認者は、自分が作成したソリューションを自分で承認することができます。 ソリューションの自己承認を許可しません。
すべてのワークステーションへのリモートデスクトップ接続を有効にする?[デフォルトは"はい"] すべてのワークステーションへのリモートデスクトップ接続を有効にします。 すべてのワークステーションに対し、リモートコントロールができません。
依頼者にモバイルアプリケーションへのアクセスを許可[デフォルトは"いいえ"] 依頼者は、モバイルアプリケーションにアクセスできるようになります。 権限のない依頼者は、モバイルアプリケーションにアクセスできません。
APIキーの自動生成を許可[デフォルトは"いいえ"] 自動でAPIキーを生成できます。 自動でAPIキーは生成されません。
ログインしていないユーザーにソリューション表示を許可する ログイン資格のないユーザーにもソリューションが表示されます。 ログイン資格のないユーザーにはソリューションは表示されません。
ログイン時にドメインフィルターを有効にする ドメインフィルターのオプションを表示します。 ログインの際ドメインフィルターを非表示にします。
  • リクエスト承認メールを送信する際の制限タイプを選択:リクエストを承認できるユーザータイプ、もしくは承認者を選択できます。管理者は、「誰でも承認可能」、「システムユーザーのみ承認可能」、「サービスリクエストの承認者のみ承認可能」のいずれかより選択します。

  • リクエストの自己承認を許可(「自己承認」は、依頼者、そして、ユーザーとログインしている技術担当者の代理も含みます）: 依頼者は自分のリクエストを承認することができます。ここでの依頼者は、ユーザーとログインしている技術担当者の代理人も含みます。

  • リクエストの承認依頼中はリクエストのタイマーを停止して次のステータスに変更する「Onhold」（デフォルトは"無効"）： リクエストの承認を依頼している間は、ヘルプデスクチームは依頼者に返信することができません。そのため、承認依頼中のSLA違反を回避する目的で、「承認依頼中」ステータスとして、リクエストのタイマーを停止することができます。このオプションを有効にするには、チェックボックスを選択します。ドロップダウンから、リクエストのステータスを選択します。

    メモ：ドロップダウンには、タイプが進行中かつ、タイマーが停止中のリクエストステータスが表示されます。承認者により、決定が下されると、タイマーの停止は自動的に解除されます。

  • 外部に公開するURLを設定する:代替URLを指定するには、
    • 1.http:// 横のテキストフィールドにURL（必要ならポート番号も）を入力します。
    • 2.URLエイリアスが正しく設定されているかを確認するため、テキストフィールド下の「ここをクリックして入力したURLを確認」をクリックします。

  • 最大添付サイズ(MB) を指定する:所定のスペースに、最大の添付ファイルのサイズを入力できます。デフォルトの最大添付サイズは、10 MBです。

  • 添付ファイルの保存パスを設定する:添付ファイルを保存する特定のパスを設定します。「リセット」オプションをクリックすると、指定したパスをリセットできます。
    メモ：パスを指定しない場合は、デフォルトのパスを添付ファイルの保存に利用します。

  • ログインページとヘッダーに表示するイメージをカスタマイズする:
    ロゴ画像の挿入： 任意のロゴを表示するようにアプリケーションをカスタマイズすることができます。ログインページのロゴ画像とログイン後の画面のヘッダー左上のロゴ画像を変更することが可能です。両方を変更する場合は、2つの画像をアップロードする必要があります。ログインページの画像は、252 px x 61 px (W x H)、ヘッダーの画像は、166 px x 46 pxです。

    ログインページの画像をインポートするには;
    • 1.イメージのインポート...をクリックします。
    • 2.参照ボタンをクリックします。
    • 3.選択ウィンドウから、インポートする画像を選択して、「開く」をクリックします。
    • 4.インポートをクリックします。

    ログインページの画像がインポートした画像に変更されます。ヘッダーの画像についても同様の手順を実施します。 保存をクリックします。
