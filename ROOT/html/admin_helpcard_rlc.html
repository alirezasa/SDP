Request life cycle is basically a clear documentation of the stages an incoming request must pass through before it can be closed.

By configuring a request life cycle, administrator defines a clear workflow for the request, providing a guided path for the technician to follow for all the assigned requests. That is, a life cycle ensures that there is no deviation from the defined request workflow.

The next possible status/es for the request is displayed in the Request Details page.

A life cycle can be associated with multiple templates for efficient request tracking and closure. However, you cannot associate more than one life cycle for a template.

On the Request Life Cycle home page, you can view, delete, and search through all the Active and Inactive Life Cycles.

To configure a new request life cycle, click New, fill out the displayed fields, and associate the necessary templates.

The displayed flowchart contains nodes, which are the actual status/es of the life cycle, and transitions, which are the actual processes that occur in that status. Depending on how you configure each transition, the Request Details page will display to the technician the next possible transition/s for the request after that status.

The flowchart is prepopulated with various statuses and transitions. To add a new stage or status to the life cycle, drag it from the panel on the right. These statuses listed in the right panel are preconfigured under Admin>>Help desk Customizer>>Status.

To connect two statuses by a transition, hover over a stage, click the plus (+) sign that appears and drag it to the target status. Then, name the transition by clicking the plus sign.

Start & End nodes merely represent request entry and closure, respectively. Any number of transitions can be connected from the Start node to any stage. Similarly, any number of transitions can be connected to the End node only from Completed statuses.

The Start node must be connected to the default status/es configured in the templates that you have associated to the life cycle.

Connecting any Completed status and any Stop-Timer status is not allowed. Similarly, connecting more than one transition to a Pending status from a Completed status that is connected to the End node is not allowed.

The various phases and configurations within a transition are as follows:

Before : Here, the administrator defines who can perform the transition and under what conditions.

During : Here, the administrator defines the fields that must be filled and the rules to be executed for moving to the target status.

After : Here, the administrator defines the rules that must be executed when the request reaches the target status.

Configuring Transitions

Click any transition to add configurations for that status.

The Start transitions can be configured with rules that can be executed only During and After the status.

For all other transitions, you can configure rules to be executed Before, During, and After the corresponding status.

Select a transition and click Before, During, or After.

Under Mandate, select the fields that must be filled out by the technician, if the request must move from that stage.

Under Optional, select the non-mandatory fields for that stage.

Note: All the Request fields except multi-select, check box, and Service Category-specific additional fields will be listed in the drop-down.

Configuring Rules for Transitions

The Rule under Before is a precondition for the request to be moved into the corresponding status. This will also include the Role/s for whom the transition will be made visible.

Rules under During and After are configured with Actions to be executed if the request meets the criteria provided. You can configure a maximum of 10 rules and turn on cascade execution.

Click Save Draft or Publish after making all the required configurations. Note that only published life cycles will be applied to the incoming requests.
