요청 수명 주기는 기본적으로 접수되는 요청서가 종료되기 전에 거쳐야 하는 단계에 대한 명확한 문서입니다.

요청 수명 주기를 구성하여 관리자는 요청서에 대한 명확한 워크플로를 정의하고 배정된 모든 요청서에 ​​대해 기술자가 따라야 할 안내 경로를 제공합니다. 즉, 수명 주기는 정의된 요청서 워크플로에서 벗어나지 않도록 합니다.

요청서에 대한 다음 가능한 상태는 요청서 세부 정보 페이지에 표시됩니다.

효율적인 요청서 추적 및 종료를 위해 수명 주기를 여러 템플릿과 연계할 수 있습니다. 그러나 한 템플릿에 대해 둘 이상의 수명 주기를을 연계시킬 수는 없습니다.

요청 수명 주기 홈 페이지에서 모든 활성 및 비활성 수명 주기를 보고, 삭제하고, 검색할 수 있습니다.

새 요청 수명 주기를 구성하려면 새로 만들기를 클릭하고 표시된 필드를 채우고 필요한 템플릿을 연계합니다.

표시된 순서도(플로차트)에는 수명 주기의 실제 상태인 노드와 해당 상태에서 발생하는 실제 프로세스인 전환이 포함됩니다. 각 전환을 구성하는 방법에 따라 요청서 세부 정보 페이지는 해당 상태 이후에 요청서에 대해 가능한 다음 전환(들)을 기술자에게 표시합니다.

순서도(플로차트)는 다양한 상태 및 전환으로 미리 채워져 있습니다. 수명 주기에 새 스테이지 또는 상태를 추가하려면 오른쪽 패널에서 끌어다 놓습니다. 오른쪽 패널에 나열된 이러한 상태는 관리 설정>>헬프 데스크 사용자 정의 도구>>상태에서 사전 구성됩니다.

한 전환으로 두 상태를 연결하려면 한 스테이지 위로 마우스를 가져간 후 표시되는 더하기(+) 기호를 클릭하여 대상 상태로 드래그합니다. 그런 다음 더하기 기호를 클릭하여 전환 이름을 지정합니다.

시작 및 종료 노드는 각각 요청 시작 및 종료를 나타냅니다. 시작 노드에서 모든 단계로 전환을 원하는 수만큼 연결할 수 있습니다. 마찬가지로, 완료 상태(들)에서만 종료 노드에 여러 전환을 연결할 수 있습니다.

시작 노드는 수명 주기에 연계된 템플릿에 구성된 기본 상태에 연결되어야 합니다.

완료 상태와 중지 타이머 상태를 연결하는 것은 허용되지 않습니다. 마찬가지로 종료 노드에 연결된 완료 상태에서 대기 상태로 둘 이상의 전환을 연결하는 것은 허용되지 않습니다.

전환 내의 다양한 단계 및 구성은 다음과 같습니다.

이전(Before) : 여기에서 Admin 관리자는 누가 어떤 조건에서 전환을 수행할 수 있는지 정의합니다.

도중(During) : 여기에서 Admin 관리자는 대상 상태로 이동하기 위해 채워야 하는 필드와 실행할 규칙을 정의합니다.

이후(After) : 여기에서 Admin 관리자는 요청서가 목표 상태에 도달했을 때 실행되어야 하는 규칙을 정의합니다.

전환 구성

전환을 클릭하여 해당 상태에 대한 구성을 추가합니다.

시작 전환은 상태 도중 및 이후에만 실행할 수 있는 규칙으로 구성할 수 있습니다.

다른 모든 전환의 경우 해당 상태 이전, 도중 및 이후에 실행되도록 규칙을 구성할 수 있습니다.

전환을 선택하고 이전, 도중 또는 이후를 클릭합니다.

요청서가 해당 스태이지에서 이동해야 하는 경우 필수에서 기술자가 작성해야(채워야) 하는 필드를 선택합니다.

선택에서 해당 스테이지의 필수가 아닌 필드를 선택합니다.

참고 사항: 다중 선택, 확인란 및 서비스 범주별 추가 필드를 제외한 모든 요청서 필드가 드롭다운에 나열됩니다.

전환 규칙 구성

이전(Before) 의 규칙은 요청서가 해당 상태로 이동하기 위한 전제 조건입니다. 여기에는 전환이 표시될 역할도 포함됩니다.

도중(During) 및 이후(After)의 규칙은 요청서가 제공된 기준을 충족하는 경우 실행할 액션으로 구성됩니다. 최대 10개의 규칙을 구성하고 연속 단계적 실행을 켤(시작할) 수 있습니다.

모든 필수 구성을 완료한 후 드래프트 저장 또는 게시를 클릭합니다. 게시된 수명 주기만 수신 요청에 적용됩니다.
