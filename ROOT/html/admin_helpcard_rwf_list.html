Establish a directional path for the service release process to adhere to using release workflow. You can define workflows for different service releases specific to your organization, associate them with release templates, and provide privileged (role-based) access for technicians to release stages.

Click New Workflow. In the workflow editor, you can add the release stages, specify conditions and switches, configure notifications, approval and field updates using nodes. Connect the source and target nodes using your cursor to specify the workflow path.

  • Using the Hamburger icon, you can edit, copy, delete a release workflow, mark it as default or change the workflow type.
  • You can also copy a workflow by selecting the workflow and clicking the Copy Workflow button.
  • View the template(s) associated with a workflow by clicking the Link icon beside the workflow.
  • To delete the release workflow in bulk, select the workflows and click the Delete icon.

Note: You cannot delete the default workflow.

Inactive Workflows:

If a workflow is deleted while associated with release requests, the workflow will be marked as inactive. To restore an inactive workflow,

  1. Go to Inactive Workflow filter.
  2. Select the workflow to restore and click Mark As Inactive.
Invalid Workflows:

If any admin configuration used in the workflow is deleted, the workflow becomes invalid and is indicated with an Exclamatory icon. For example, if the additional field "Release Type" configured in a workflow is deleted from Admin >> Release Additional Fields, the workflow will become invalid.

You can find the reason for the workflow becoming invalid in the workflow history. Edit an invalid workflow and reconfigure the flow to validate it.

Although you can edit or delete invalid workflows, you cannot copy, change workflow type or set invalid workflows as the default workflow.
