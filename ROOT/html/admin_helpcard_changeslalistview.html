Service Level Agreements help you define the time within which a Change Request needs to be resolved. SLAs are applied automatically during 'Add/Update' of Change Requests based on certain criteria which you can define.

Change SLA will be executed based on the 'Scheduled Start' and' Scheduled End' time of the Change Request.This page allows you to configure and update Change SLA. SDAdmin can create Change SLA.

In Change SLA List view, you can enable/disable Escalations by choosing 'Enabled/Disabled' in 'All Mail Escalations'.

The Change SLA is applied to Change Requests in the order in which they are defined. Drag and Drop the Change SLA to re-order the list. Click 'Apply Changes' to save the new order. Click 'Cancel' to revert to the original order.

In Change SLA list, click on the 'Enable/Disable' option on the right of the check-box in order to enable/disable the SLA. If you want to delete some of the SLAs, select the required SLAs and click 'Delete'.

Add New 'Change SLA':

To add a new SLA, click 'New' ,which is present next to the 'Change SLA list'. You will be directed to 'Create Change SLA' page. Provide a name for the 'SLA' created. The name provided has to be unique for each SLA created and it is a mandatory field. You can provide a brief explanation of the SLA in the Description field.

You can select whether the Change SLA is to be executed in either 'Operational hours' or 'Calendar hours' by clicking on the corresponding Radio Button.

If you want the Change to be resolved with respect to the working hours, choose 'Operational hours'.

If you want the Change to be resolved irrespective of the working hours, choose 'Calendar hours'.

'Match All/Any of the following Criteria', helps you define the criteria for classifying the incoming Changes. Select 'All' or 'Any' from the switch button, as per the requirement.

You can select the desired field from the fields listed and select the corresponding value(s). The SLA will be matched to the Change Requests based on this criteria.
Example :If you define a SLA by name 'High Impact SLA' and set the SLA criteria as 'Impact is High' ,then all incoming Change Requests having Impact = High, will be matched to that SLA.

More than one criteria can be set or removed by clicking on '+/-'.

If the 'Resolution Time'is to be defined as per the SLA, click 'Yes' and select the number of days and hours within which the Change has to be resolved.The 'Scheduled End' time will be calculated based on the 'Scheduled Start' time of the Change and the configured resolution time.

There are certain Change processes, where one cannot define predefined resolution time in a SLA. If you do not want to define the Resolution time, click 'No'. In such cases, the escalations is defined in terms of percentage of the Total Time ('Schedule Start' Time to 'Schedule End' Time).

The Change can be subject to various escalation levels before/ after the Resolution time.

Change SLA Related Escalations

Up to 4 levels of escalation can be defined for each SLA.The Change will be escalated to all the configured 'Change Roles' users, if the Change is not yet resolved at the specified time.

If 'Yes' is chosen for 'Do you want to define the Resolution Time?', the escalations are defined as 'Before/After' the 'Scheduled End' time. Enter the days/hours and the 'Change Roles' to whom the escalation is to be sent.

If 'No' is chosen for 'Do you want to define the Resolution Time?', the escalations are defined as percentage of time span between 'Scheduled Start' and 'Scheduled End' time. Choose the percentage of time span and the 'Change Roles' to whom the escalation is to be sent.

Click the 'Save' button to save the SLA and return to the list view. Click the 'Save and Add New' button to save the SLA and add another SLA.
