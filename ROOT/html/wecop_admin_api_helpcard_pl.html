ServiceDesk Plus API

Ten dokument wyjaśni użycie API w ServiceDesk Plus, do wykonywania operacji na zgłoszeniach poprzez protokół Http.

Wytyczne API

SDP wspiera API poprzez protokół Http dla wykonywania opercji na zgłoszeniach. Wartości pól do ustawienia w zgłoszeniu, będą dodawana jako parametry w szczegółach żądania. Formularz musi być wysłany do /servlets/RequestServlet (jako http://nazwa_serwera:Numer_Portu/servlets/RequestServlet). Pola niedostępne jako parametry w żądaniu będą ustawione jako puste (lub domyślne). Autoryzacja do SDP oparta jest o nazwę użytkownika i hasło. Można wykonać akcje Dodania zgłoszenia, Poprawy zgłoszenia, Przydzielenia/Podjęcia zgłoszenia, Zamknięcia zgłoszenia, Usunięcia zgłoszenia, Dodania notatki, Podglądu szczegółów zgłoszenia poprzez API. Przeprawadzane akcje będą rozpoznawane w oparciu o paramerty http 'akcje'. Zwróć uwagę, że akcje i atrybuty są wrażliwe na wielkość znaków i powinny być używane tak jak zostały zdefiniowane.

Dodaj zgłoszenie:

Szczegóły niezbędne dla dodania zgłoszenia powinny być ustawione w parametrach zgłoszenia, a wartość parametru zgłoszenia dla 'akcji' powinna być 'AddRequest'.

Oddzwoń :

Statusem operacji na servletach będzie plik xml zawierający 'OPERATIONSTATUS', 'MESSAGE', 'WORKORDERID' [tylko dla nowych zgłoszeń]

Rozwiązywanie problemów :


Tworząc nowe zgłoszenie :
  1. Zgłoszenie będzie utworzone z dostępnymi informacjami wprowadzonymi przez użytkownika.
  2. Podczas tworzenia zgłoszenia w części login zgłaszającego, 'lokalizacja' dla użytkownika będzie ustawiona jako lokalizacja do której zgłaszający należy.
  3. W żadnej lokalizacji, może byc określone jako puste pole lub 'NULL' dla lokalizacji [tylko logowanie serwisanta].
  4. Podczas tworzenia zgłoszenia, zgłaszający będzie ograniczony do utworzenia zgłoszenie dla zasobu przydzielonego do niego, jeśli opcja 'Pokaż komputery przydzielone do zgłaszającego w Portalu pomocy technicznej' będzie zaznaczona w module Administracja -> Ustawienia portalu pomocy technicznej.
  5. Jeśli serwisant z ograniczonym dostępem do lokalizacji, utworzy zgłoszenie dla lokalizacji do której nie jest przydzielony, wtedy lokalizacja w zgłoszeniu zostanie ustawiona jako 'W żadnej lokalizacji' .
  6. Jeśli 'Temat' nie jest wprowadzony podczas tworzenia zgłoszenia, '(bez tematu)' zostanie ustawione jako temat zgłoszenia.
  7. Jeśli informacja 'requester' nie zostanie podana, wtedy pole zgłaszający zostanie ustawione jako 'Zgłaszający' w zgłoszeniu.
  8. Jeśli wymagane pole, określone w 'Szablonie zgłoszenia' nie zostaną wprowadzone podczas dodawania zgłoszenia, zgłoszenie zostanie utworzone z informacjami wysłanymi do 'RequestServlet' i pojawią się błędy w 'System Log'.
Podczas poprawy zgłoszenia :
  1. Zgłaszający nie mają uprawnień do poprawy w zgłoszeniach.
  2. Pusta wartość dla pola może być określona jako 'NULL'.

Jeśli logowanie się nie powiedzie dla poprawnej 'Nazwy użytkownika' i 'Hasła',

  1. Sprawdź czy użytkownik został zaimportowany z 'Active Directory'.
  2. Jeśli użytkownik nie jest zaimportowany z 'Active Directory' upewnij się, że 'nazwa użytkownika' i 'hasło' jest wysyłane do 'http://nazwa_serwera:numer_portu/servlets/RequestServlet' do autentykacji.
  3. Jeśli użytkownik jest zaimportowany z 'Active Directory', wtedy 'nazwa użytkownika' i 'hasło' jest wysyłane razem z 'nazwą domeny' i 'nazwą logowania' do 'http://nazwa_serwera:numer_portu/servlets/RequestServlet' do autentykacji. Nazwa domeny 'DOMAIN_NAME' reprezentuje domenę do której należy użytkownik. Nazwa logowania 'logonDomainName' reprezentuje tryb autentykacji. 'Lokalna autentykacja' lub puste pole odnosi się do lokalnej autentykacji, 'AD_AUTH' odnosi się do trybu autentykacji Active Directory.
