Delimiter

It`s difficult for users to distinguish between notifications from multiple modules. So, here comes the role of a delimiter which allows the users to filter the notifications and identify their source.
Example:
If a notification has the delimiter '##RE-123##', then the user can identify the source of the notification to be the Request (RE) module.

The tickets processed by e-mail are added as either new tickets or conversations. For a ticket to be added as a conversation, the 'request ID' in the ticket should be the same as the 'parent ID' of the delimiter in the subject of the notification.

The default base delimiter value is ## which users can modify. Once the user alters the base delimiter value, all the relevant notification`s content title will be automatically updated with the new delimiter value.
Example:
Consider the notification rule 'E-mail acknowledgment to requester on submitting a new request' (under 'Admin >> Notification Rules'). By default, the subject of the notification will read as follows: 'Your request has been logged with request id ##RE-$RequestId##'. Here, if the user modifies the base delimiter value as @@ instead of ##, then the subject will change as follows: 'Your request has been logged with request id @@RE-$RequestId@@'.
