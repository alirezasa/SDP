On this page, you can configure service level agreements (SLAs) and associate operational level agreements (OLAs) with them. SLAs define the time within technicians must respond to and resolve requests.

The Add New SLA form has three blocks of information:

  • SLA Details

    • Enter a unique name and description for your SLA.

  • SLA Rules

    • Set a rule for your SLA. You can choose between Match ALL of the following or Match ANY of the following. Then, select a criterion and click Choose to set a value.

    • Set the first response and resolution time for the request. You can define if the SLA must be applied irrespective of operational hours, holidays and weekends.

  • Escalations

    • Select an escalation level and the technicians to notify, if the first response time/resolution time limit is exceeded.

    • To escalate a request before the SLA is violated, choose Escalate Before and set the time of escalation.

    • Click Escalate After to escalate after the violation.

    • Click Actions to configure a technician, group, priority and level of the request after escalation. 

Note: In the Group drop-down, the default support groups will be listed. Similarly, in the Technician drop-down, technicians who are not associated with any sites will be listed.

You can configure different sets of actions for all the 4 escalation levels associated with the resolution time.

Operational Level Agreement

Operational Level Agreements (OLA) define how various IT groups within a company plan to deliver a service. You can configure OLAs for every SLA to decide how the SLA can be achieved by the internal groups working on the request.

  • Fill in the relevant information:

    • Group Name - Enter the group/s which will handle the requests.

    • OLA Time - Set the time within which the selected groups must resolve each request.
