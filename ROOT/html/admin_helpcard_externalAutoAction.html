You can define rules to automatically invoke any custom class or script file. The action rules can be applied to a request when it is created, (or received) or edited or both

 

Adding a New Action Rule

 

To add a new Action Rule, click Add New Action link on the top right corner of the Request Custom Action list page.

 

Specify a unique Action Name to identify the integration.

If you wish to describe the action rule in detail, you can enter the content for the same in the Description text box.

Choose one of the two execute options from the Execute the Action drop down.

  • When a Request is created - Select this option to apply the rule when a request is created.
  • When a Request is edited - Select this option to apply the rule when a request is edited.
  • When a Request is created and edited - Select this option to apply the rule when a request is created and edited.
  • When a Request is approved - Select this option to apply the rule when a request is approved.
  • When a Request is rejected - Select this option to apply the rule when a request is rejected.
  • When a Request is approved or rejected - Select this option to apply the rule when a request is approved or rejected.
  • When a new reply received - Select this option to apply the rule when a new reply received for a request.

You can define the rules and set matching criteria based on the incoming requests (form based requests and e-mails). For the requests that match the criteria, the specified executor will be invoked and the appropriate action will be carried out without any manual intervention.

 

From the Criteria combo box, select the specific criteria, and then select the matching Conditions from the combo box. Click Choose button to add the specific values. You can choose to match all the criteria set by selecting 'and' option or match any of them by choosing 'or' option from the drop down. You can click Add another criteria link to add more rules with the criteria and conditions.

 

Now set the appropriate actions that need to be performed on the requests that match the above criteria that you have added.

 

Under Perform Action, choose whether you want to execute class, script, or custom function and configure the same using the following pointers:

  • Class: Specify the Executor class. For example, com.servicedeskplus.integration.JiraActionImplementation.
  • Script: Specify the name and path of the script file. For example, cmd / c Index.bat. The script will run from [SDP_Home]/integration/custom_scripts.
  • Custom Function: By executing custom functions, you can manipulate data in ServiceDesk Plus and other external applications. requestObj and context are the arguments supported in custom functions.

Note: In a script, you can pass all API parameters as arguments, whereas requestObj and context are the arguments supported in custom functions.

Examples 

For Script : cmd / c Index.bat $COMPLETE_V3_JSON_FILE

For Class  : com.servicedeskplus.integration.JiraActionImplementation

Some of the Other Parameters Supported

$COMPLETE_V3_JSON_FILE ---> Complete Request Object will be saved to a JSON file and the file path will be passed as String Object. If the Operation is When a Request is edited, then DIFF_JSON (difference between the old request data and new request data) will also be saved to a JSON file.

JSON File Path  : (SDP_Home\integration\custom_scripts\request\12_1426143538036.json).

Email and SMS Notification 

You can notify users about a high priority request via Email or SMS right when it is created. To configure a notification, click Add beside the preferred mode and choose the required template. Add the email recipients and click Save. You can also create templates for these notifications from the template drop-down.

By default, the Stop processing subsequent Actions check box is enabled and the execution of the action will stop once a rule is applied on a request. On deselecting this option, execution of successive action will continue (as per the action rule order) even after an action rule is applied on a request.

 

Organizing Custom Triggers
To organize the Actions, click the Organize Actions link and in the pop-up, select the business rule and click Move up or Move Down button. It decides the order in which the rule is applied on the incoming request.
