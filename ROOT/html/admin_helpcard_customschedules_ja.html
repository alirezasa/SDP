カスタムスケジュールを利用して、ServiceDesk Plusの任意のデータにアクセスし、通知の送信、リクエストの再オープン、資産情報の更新などの、カスタマイズした定期的なスケジュールアクションを実行することができます。 また、カスタマイズしたスクリプトファイルに、アクションを記載することもできます。 ServiceDesk Plusのデータを、クエリレポートを用いて特定のスクリプトへ送信することができます。

カスタムスケジュールを作成するには、以下の情報を参考にしてください：

スケジュールの詳細情報：一意の「スケジュール名」と、 それに関連して、カスタムスケジュールが何を行うかの「説明」を入力します。 「有効」のチェックボックスを利用して、カスタムスケジュールを有効化/無効化できます。

実行対象：スクリプトを使用して実行するアクションを指定します。 サードパーティーアプリケーションや、Zohoの組み込みのスクリプティングアプリケーションである、Delugeを用いたスクリプトを実行できます。

  • スクリプトを実行する - スクリプトを含んだテキストファイル名を指定し、該当のテキストファイルを＜インストールディレクトリ＞/integration/custom_scripts/executor_filesディレクトリに保存します。 ServiceDesk Plusは、＜インストールディレクトリ＞/integration/custom_scripts/フォルダーから、指定されたファイルを読み込み、スクリプトを実行します。
    • テキストフィールドには、スクリプトを読み込むため、py filename.pyコマンドを用いてスクリプトファイルを指定します。
  • カスタム関数を実行 - カスタムスケジュール関数で、Delugeを用いてスクリプトファイルを作成し保存します。 ドロップダウンリストから、関連するスクリプトを選択します。 ドロップダウンリストからは、［新規関数の作成］で、カスタムスケジュール関数を新規作成することもできます。
    • カスタムスケジュール関数について、詳しくはこちらをご覧ください。

変数： 変数としてデータを用いる、クエリレポートを選択します。 レポートは［レポート］タブ配下のフォルダーに保存されていることを確認してください。 最大3つのクエリレポートを関連付けることができます。

どのようにしてクエリレポートを変数にするのか

スケジュールが開始されると、関連付けられたクエリレポートが生成され、その結果がJSONファイルとして＜インストールディレクトリ＞/integration/custom_schedule_reports/に保存されます。 このJSONファイルパスが、カスタムスケジュールの実行対象へ変数として渡されます。

クエリレポートで、「優先度がHighで、SLA違反したリクエスト」のレポートが次の用に出力されたと仮定します：

リクエストID 件名 技術担当者
47 Unable to fetch mails Heather Graham
128 Cannot connect to MSSQL server Shawn Adams

すると、JSONファイルの結果は以下のようになります：

[
    {
        "リクエストID":"47",
        "件名":"Unable to fetch mails",
        "技術担当者":"Heather Graham"
    },
    {
        "リクエストID":"128",
        "件名":"Cannot connect to MSSQL server",
        "技術担当者":"Shawn Adams"
    }
  ]

アクションが実行されると、JSONファイルは削除されます。

開始日 & 時間： カレンダーアイコンから、カスタムスケジュールの実行を開始する日付と時間を選択します。 選択した日付と時間がカスタムスケジュールの作成/編集日よりも前の場合、そのアクションはカスタムスケジュールを保存後すぐに実行されます。

繰り返し：ドロップダウンリストから、カスタムスケジュールを繰り返す頻度を選択します。

注意：

カスタムスケジュール一覧ページの「結果」カラムには、対象のアクションの最新の実行結果が出力されます。

実行されたアクションの詳細な結果については、［クイックアクション/コミュニティ］>［システムログビューア］から確認できます。
