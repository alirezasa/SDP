Configure incoming mail server settings for your organization to receive emails from users.
You can use email protocols (POP, IMAP, POPS, or IMAPs), Exchange Web Services (EWS), or Microsoft Graph to connect application with the mailbox.
Depending on the connection protocol selected, the configurations may vary. Click the pointers below to understand how to configure each connection protocol.
POP / IMAP / POPS / IMAPS
FieldExplanation
Authentication Type
  • Use Basic authentication to authenticate mailbox using credentials
  • The application supports OAuth 2.0 Authentication. Know more.
Server Name/IP Address

Mention the name or IP address of the mail server.
Username

Enter the username of the mailbox.
Password (For Basic Authentication only)

Enter the password to access the mailbox.
Email Address

Enter the email address from where the emails must be fetched. You can mention alias email addresses, if any. To learn more, refer to the admin guide.
Protocol

Select the protocol (POP, IMAP, POPs, or IMAPs) to connect to the mailbox.
Port

Specify the port number as per the selected protocol.
Authorization Server Details (For OAuth Authentication only)

Obtain Client ID, Client Secret, Authorization URL, Token URL from the Authorization Server as discussed here.

Configure Redirect URL in the authorization server to obtain tokens.

In the Scope field, define the accessibility of the obtained OAuth tokens in the mailbox. Know more about default values populated as scope.
Note: If you are using Office365 GCC High mailbox, ensure the TLD (top-level domain) is .us in the hostname, connect URL, authorization URL, token URL, and scope.

  • Enter the time interval to fetch mails.
  • Enable proxy server, if the application requires proxy to connect to the mailbox.
  • Enable email debugging to identify accurate traces related to mail fetching issues.
  • Restrict processing emails as requests by selecting the Disable request creation by email checkbox
    • You can specify certain email addresses that can be processed for raising requests. For example, heather@zylker.com.
    • You can also specify domains that can processed for requests by entering asterisk (*) followed by @domain name. For example, *@zylker.com.
  • You can move error emails to a separate folder to prevent them from stopping the mail fetching schedule
    • Provide a name for the error folder.
    • Choose if you want to stop the mail fetching process after a specified number of mails.
    • The total number of mails in the error folder will be displayed in UI. You can move them to the inbox if needed.
    • Enable the notification to receive an alert when emails are moved from the error folder to the inbox.
    • You can download the error logs if needed.
  • Click Save.
