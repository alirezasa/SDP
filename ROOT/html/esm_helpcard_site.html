When a company has several branches in various regions, each branch is configured as a separate site, under a region.

Sites can be imported from AD or CSV via Users section, or added manually only under the ESM Directory. Deleting or editing a Site is possible only under the ESM Directory. Here, generic details such as the address, contact details, and Org Roles of the Sites can be managed.

Benefits of adding a site

  • Helps in segregating and identifying issues by sites.
  • Helps in generating site based reports.

Benefits of adding site based org roles

  • Helps in easier selection of site approval authority for incident and service requests.
  • Helps in looping the site authority on crucial notification configurations.
Related settings for each site must be managed only under the corresponding service desk instance.

Note: Departments will not be available under Related Settings.

Inactive sites will be changed to active state in the following scenarios:

a. After a successful Active Directory import.
b. CSV Import of users and assets.

Inactive sites will not be auto activated in the following cases:

a. Creating requests through E-mail Command for an inactive site.
b. Using API to create and editing requests, asset, technician for an inactive site

Deleting Sites

The sites that do not have any entities like Users, Assets, Departments, Preventive Maintenance tasks, and Incident templates associated with them can be deleted in one go. However, sites with entity associations require reassigning of those entities to a different site before you delete them.

Moving associated entities to a different site

If users are associated with a site you are deleting, then a pop-up will be shown alerting you to move the user association to a different site. If a user's department does not exist in the new site you are associating, then a new department will get created under the new site.

Note: Assigning a different site to the user association is a mandatory for site deletion. This action can only be performed by Org Admin. If you move a user association to a different site, then there are chances that a user may move out of an instance or get added into an instance depending upon the instance user import criteria.

Instance specific entity movements

Instance specific entity movement such as Asset, PM Task, Request Template, Referring Sites, Instance user import criteria needs to be completed by the instance owners. Whenever a site with instance specific entities is deleted, a notification prompting to move the associated entities to a different site will be sent to respective instance owners. If all the portal specific entity movements are completed, then the site will either be removed from the application or remain in the inactive site list based on the association with modules.
