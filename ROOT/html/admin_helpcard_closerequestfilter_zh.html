请求关闭规则可用于选择技术员在关闭请求时要填写的必填项。您也可以用它来确认用户对技术员的认可，并手动或自动关闭请求。

比如： 如果您选择解决方法作为此页的必填字段，那么无论哪位技术员解决问题，都应当在解决方法文本字段为问题输入原因和解决方法 ，否则就会弹出错误信息框，询问您是否在解决方法字段输入了信息。如果是的，提示信息选项启用，那么将向相关技术员提示是否用户已经确认了解决方法的信息。

要设置请求关闭规则，

  1. 通过启用复选框从列表中选择关闭申请的必填项。

  2. 如果您想需要提示技术员是否用户已经确认了解决方法，那请启用是的，提示信息按钮，否则，启用不提示信息按钮。

  3. 通过选择 '移动请求状态到' 复选框并从下拉菜单选择选择已关闭（或）已解决选项，在相关任务完成后启用请求关闭。

  4. 一个请求可以手动或自动关闭。

手动关闭：在启用这个单选按钮后，请求一旦解决就必须由相关技术人员手动关闭。

自动关闭：一旦请求处于解决状态，将向请求者发送一封电子邮件。请求者可以使用提供的链接关闭请求，或者通过回复邮件重新打开请求。如果请求者不采取任何行动，那么请求会在组合框中指定的天数后被关闭。

启用自动关闭按钮。在将已解决（Resolved）的请求自动关闭的等待时间组合框中选择关闭请求的天数。

如果审批被拒绝，则自动关闭请求

启用此选项，当请求的批准被拒绝时，将自动关闭一个请求 - 即，如果一个请求的批准状态被改为 "拒绝 "状态。通常情况下，管理员/技术员必须在请求的批准被拒绝时手动关闭请求，但是有了这个选项就不需要了。

有此，您可以：

  1. 配置一旦批准被拒绝后，请求应被关闭的时间。使用天数和小时的下拉菜单来配置它。
  2. 选择一个合适的请求关闭代码
  3. 在给定的字段中添加请求关闭的注释（如果有的话）。
  4. 配置应该如何处理与请求相关的待办任务 - 例如，您可以配置待办任务的状态改为 "关闭"、"解决 "或一些自定义的完成状态，否则您可以配置在批准被拒绝时删除这些任务。

注意：只有当申请的批准状态变为 "拒绝 "状态时，请求才会被自动关闭。
