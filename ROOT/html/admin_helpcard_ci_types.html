CI Types

Configuration Item Types denote the broad classification used to categorize the Configuration Items in your organization.

Use the New button to add a CI type. You can specify the CI type details, customize fields to be added to each CI type, and define relationships between CI types.

Click the Actions icon to edit a CI type, create child CI types, or delete a CI type. API names cannot be edited.

Click the Search icon on the toolbar to search through the list view columns.

Add CI Type

You can create CI types as templates with which you can categorize your CIs. A CI type contains fields which are specific to all the CIs under that CI type/child CI type.

Create CI Type
  1. Click New.
  2. Provide a unique display name and display plural name.
  3. The API name and API plural name will be populated automatically in snake_case. You can modify them, if needed.
  4. Specify the category of the CI type.
  5. Select a parent CI type from the available list.
  6. Add an icon, if required.
  7. Describe the CI type.
  8. Click Save.
Configure fields

The parent attribute fields will be auto-populated. You can add fields specific to the child CI type.

  1. In the Fields tab, drag and drop the desired field type from the left pane.
  2. Click Add icon to create additional fields.
  3. Click View All to associate additional fields with the CI type.
  4. Hover over a section and click Edit icon to modify the section properties and customize the layout.
  5. Hover over a field to edit or delete it from the template.
  6. Click Save.
Define Relationship with other CIs

In the Relationship tab, click New.

Fill out the configuration details as explained below:

  • Source CI Type: The source CI type is auto-selected.
  • Relationship Type: Define the relationship type.
  • Related CI Type: Select the CI type to which the source CI type is associated with.
  • Cardinality: Define the numerical relationship between the records in source and related CI types. Based on the cardinality, you can associate a source CI with single/multiple related CIs and vice-versa.
  • Display name in Source CI Type: Provide a name to be displayed in the source CI type.
  • Source CI Type API name & Source CI Type API plural name: Specify the API names for the source CI type. API names must be in snake_case and cannot be edited. By default, source CI type API names are prefixed with assoc_.
  • Field to filter list view in Source CI Type: Select filter values for the relationship list view in source CI type. Users can filter the CIs listed in the related CI type based on the fields selected in this drop-down.
  • Filter criteria in Source CI Type: Predefine criteria to filter CIs in the related CI types while displaying them in the source CI type.
  • Display name in Related CI Type: Provide a name to be displayed in the related CI type.
  • Field to filter list view in Related CI Type: Select filter values for the relationship list view in related CI type. Users can filter the CIs listed in the source CI type based on the fields selected in this drop-down.
  • Related CI Type API name & Related CI Type API plural name: Specify the API names for the related CI type. API names must be in snake_case and cannot be edited. By default, related CI type API names are prefixed with assoc_.
  • Filter criteria in Related CI Type: Predefine criteria to filter CIs in the source CI types while displaying them in the related CI type.
  • Click Save.

Configure additional fields to collect details about the relationship properties.

  • Click New Field to create an additional field for the relationship. Learn more.
  • Use the Edit icon to update an additional field.
  • To remove an additional field permanently, use the Delete icon.
  • To remove an additional field from the relationship form, select the additional field and click Dissociate.

You can also associate fields that are already available for the relationship type.
