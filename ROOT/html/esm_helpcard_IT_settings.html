SELF-SERVICE PORTAL SETTINGS

Self-Service Portal Settings allows you to select fields to be displayed in the Self-Service Portal while the General Settings allows you to configure specific settings common to all modules.

OPTION 'YES' 'NO'
'Show technicians as part of Requesters list, while creating a new request?'['Yes' by default] Allows all technicians to be requesters as well Enabling 'No' radio button will show technicians as a part of the Requesters list.
'Allow requesters to associate requests with project?'['No' by default] Enabling 'Yes' radio button will allow requesters to associate requests with the corresponding project thereby helping in mapping of request with its project. Requesters will not be allowed to associate requests with project unless sufficient privileges are given.

'Allow requesters to reopen their own requests?'['No' by default]

 Enabling 'Yes' radio button will permit the requester to re-open their own request and edit it.When the status of the request is moved to Closed or Resolved, a Reopen tab is displayed in the request details page.

Note: Automated replies like bounces, out-of-office emails will not affect the status of the request with this configuration. 		Requesters will not be allowed to reopen their own requests unless sufficient privileges are given.
'Allow requesters to close their own resolved requests?' ['No' by default] Enabling 'Yes' radio button will allow requesters to close their own resolved requests.When the status of the request is moved to Resolved, a Close tab is displayed in the request details page. Requesters will not be allowed to close their own resolved requests unless sufficient privileges are given.
'Open onhold requests upon requesters reply'['No' by default] Enabling 'Yes' radio button will open the onhold requests upon requesters reply.

Note: Automated replies like bounces, out-of-office emails will not affect the status of the request with this configuration. 		Onhold requests will not be opened upon requesters reply.
  • Select the radio buttons of the following options in order to configure the required action when the requester replies through E-mail / Portal to the closed requests :
    • ReOpen the request always.
    • Reopen the same request within days from closed time (Select the required number of days). Else, create as a new request.
    • Append the reply as conversation to the request and notify technician.
    • Create as a new request.
OPTION 'YES' 'NO'
Disable default request template for requesters ['No' by default] Enabling 'Yes' radio button will prevent the requester from viewing the default request template. The request template will be available to all the requesters.
  • Allow Requesters to Edit

    Choose which requests the requesters can edit. Select Incident/Service orboth. 

Show Service Catalog cost information to Requesters : Shows service catalog information only to the requesters. Approvers: Shows service catalog information only to the approvers.
  • Show Service Catalog cost information to: Configure whether to display service costs to all requesters or only to the approvers of the specific request.
  • Show assets associated to requester alone in Self-Service Portal checkbox can be enabled if you want the assets to be shown to the requester alone in Self-Service Portal.
OPTION 'YES' 'NO'
Status change comment mandatory for request ['No' by default] Enabling 'Yes' radio button will make comments mandatory for status change of a request. Status change comments are not mandatory for a request.
Show Suggestions to requesters while creating new Incident Request? ['Yes' by default] Automatic suggestion of Announcements and Solutions during Incident request creation will be enabled for Requesters Enabling 'No' radio button will prevent the requester from viewing any suggestions while creating a new Incident request.

APPROVAL SETTINGS:

    • Show Approval Tab to requester checkbox is Enabled by default. The Approvals Tab is shown to the requester who has initiated the request and to the requester who can approve the requests. It can be disabled if you do not want the requester to view the Approvals Tab.

    • Choose restriction type to be made while sending Request approval mails:The Administrator can choose the type of users or approvers who can approve the Approval Request. The Admin can choose from Anyone can Approve, System users only can approve and Service Request approvers only can approve.

    • Allow only logged-in approvers to take approval actions by setting Yes to Allow approval actions from logged-in users only option. However, for this functionality to work, Anyone can approve option must be disabled as both the functionalities can't coexist.

    • Allow Self Approval of Requests (Note that 'self approval' includes Requester, On-behalf-of User and Logged-in-tech: Selecting this checkbox will allow the Requester to approve his own Request. Requester here includes both On-behalf-of user and the Logged-in Technician.

    • While a request is waiting for approval, stop the timer and set request status to 'Onhold' is Disabled by default. Enabling the checkbox will stop the timer and set the status to 'Onhold' when a request is waiting for approval. In most cases, when a request is sent for approval to the concern authority, the help desk team may not be held responsible for the delay in approval process. In order to minimize the SLA violation by the help desk team, you can stop the timer for requests with status as 'pending approval'. Select the check box to avail this option. You can also select the request status from the drop-down box.

    • Approval Reminder Notification : Enable this to notify the approver if the approval action is not taken after a certain number of days. The time to send the Approval Reminder Notification can be configured as well.

    • Stop Sending Reminder Notification : Enable this to stop the notifications that are sent to the approver repeatedly. The number of notifications sent to the approver can be limited by selecting the notification count.

    • Customizing Approval reminder notification content : The content for approval reminder notification can also be customized. Tap on Click here to customize the content of the mail.

    • Approval Reminder Notification : Enable this to notify the approver if the approval action is not taken after a certain number of days. The time to send the Approval Reminder Notification can be configured as well.

    • Auto-approve requests if already approved by the same approver in the previous stages : Enable to auto-approve requests if the approver has already approved a previous stage in the request.

    • Auto-approve requests when the requester is the approver : Enable to auto-approve requests if the requester is also the approver.

GENERAL SETTINGS:

  • Currency: Specify the required currency in the given text field. This unit will be used in all places where cost calculation is done. By default, the currency is set to US dollar-USD
  • Currency Symbol: Displays the symbol of the corresponding currency. By default, the currency specified is $.
  • Start day of the week: The selected day will be considered as the starting day of the week in all the calendar views. By default, start day of the week is Sunday.
OPTION 'YES' 'NO'
Show the site details in the request details page ?['Yes' by default] The site details such as, site name, address and contact information from the request details page can be viewed.View Site details icon appears beside the site parameter in the request details page to view the site details. Enabling 'No' radio button will remove the View Site details icon from the request details page.
Combine incident and service templates listing for the service['Yes' by default] The Incident and Service Templates will be grouped according to specific categories and listed under New Request drop-down menu. Enabling 'No' radio button will prevent the incident and service templates from being combined in the listings.
Show 'Quick Create' section for technicians?['Yes' by default] The quick create section will be shown to the technicians in the home page. Enabling 'No' radio button will prevent the quick create section from being shown to the technicians in the home page.
Set requesters asset automatically for requests created through e-mail?['Yes' by default] In general, you can associate multiple assets to a requester. So while raising a request via e-mail, by default, the first asset associated to the requester is displayed. Requester's asset will automatically be set for requests created through e-mail. Enabling 'No' radio button will prevent automatic association of requester's asset for requests created through e-mail.
Can Solution approver approve his own solution? Selecting 'Yes’ will give the solution approve permission to the solution owners. There won’t be any need to send the solutions for further approval.  Selecting 'No’ will bar solution owners from approving their own solutions. It will be necessary for the solution owners to send their solution for approvals before getting it listed for users. 
Do you wish to hide solutions tab from requesters? Selecting 'Yes’ will hide the solutions tab for the requesters. Selecting 'No’, will make the solutions tab visible to the requesters. 
Hide forward option for requeters in Solutions Selecting 'Yes' will hide forward option for requesters. Selecting 'No', will make forward option visible to requesters. 
Enable Remote Control access for all workstations?['Yes' by default] Remote Control Access will be provided for all Workstations. Enabling 'No' radio button will prohibit Remote Control Access for all workstations.
Allow Requester(s) to access Mobile Application['No' by default] Enabling 'Yes' radio button will permit requester(s) to access Mobile Application. Requesters do not have access to Mobile Application unless provided with sufficient privileges.
Allow Non-login users to view solutions Enabling 'Yes' radio button will allow users with no login credentials to view solutions. Enabling 'No' radio button will prevent users without login credentials from viewing the solutions.

Remove system generated notifications for closed requests.

You can disable the system generated notification for requests that have been closed or archived. Choose the time frame and stop all the notifications for requests completed within the specified time.

Backup technician

Configure how you would like to assign a backup technician. Select Due by data of a request to assign a back up technician if the existing technician is unavailable on the due by date. Select Created date of a request to assign a backup technician if the existing technician is unavailable on the date the request gets created.
