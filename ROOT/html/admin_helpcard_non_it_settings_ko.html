SELF-SERVICE 포털 설정

Self-Service 포털 설정을 사용하면 셀프 서비스 포털에 표시할 필드를 선택할 수 있고, 일반 설정을 사용하면 모든 모듈에 공통적인 특정 설정을 구성할 수 있습니다.

옵션 '예' '아니오'
'새 요청서를 생성하는 동안 기술자를 요청자 목록의 일부로 표시하시겠습니까?'[(기본값)은 '예'] 모든 기술자가 요청자가 되는 것을 허용 '아니요' 라디오 버튼을 활성화하면, 기술자가 요청자 목록의 일부로 표시됩니다.
'요청자가 요청을 프로젝트와 연계하도록 허용하시겠습니까?'[(기본값)은 '아니오'] '예' 라디오 버튼을 활성화하면 요청자가 요청서를 해당 프로젝트와 연계할 수 있으므로 요청서를 해당 프로젝트와 매핑하는 데 도움이 됩니다. 요청자는 충분한 권한이 부여되지 않는 한 요청을 프로젝트와 연계할 수 없습니다.
'요청서 목록 보기 필터에 그룹을 표시하시겠습니까?'[(기본값)은 '아니오'] '예' 라디오 버튼을 활성화하면 기술자가 요청서 목록 보기 필터에서 그룹을 볼 수 있습니다. '아니요' 라디오 버튼을 활성화하면 요청서 목록 보기 필터에서 그룹이 숨겨집니다.

'요청자가 자신의 요청서를 다시 열도록 허용?'[(기본값)은 '아니오']

 '예' 라디오 버튼을 활성화하면 요청자가 자신의 요청서를 다시 열고 수정할 수 있습니다. 요청 상태가 종료됨 또는 해결됨으로 이동되면, 요청 세부정보 페이지에 재개봉 탭이 표시됩니다. . 요청자는 충분한 권한이 부여되지 않는 한 자신의 요청서를 다시 열 수 없습니다.
'요청자가 해결된 요청서를 종료하도록 허용하시겠습니까?' [기본값은 '아니요'] '예' 라디오 버튼을 활성화하면 요청자가 해결된 요청서를 종료할 수 있습니다. 요청서 상태가 해결됨으로 이동되면 요청서 세부정보 페이지에 종료 탭이 표시됩니다. 요청자는 충분한 권한이 부여되지 않는 한 해결된 요청서를 종료할 수 없습니다.
'요청자 응답 시 보류된 요청서 열기'[기본값은 '아니오'] '예' 라디오 버튼을 활성화하면 요청자가 응답하면 보류 요청서가 열립(진행중 상태로)니다. 보류된 요청은 요청자가 응답해도 열리지 않습니다.
  • 요청자가 마감된 요청서에 대해 이메일/포털을 통해 응답할 때 필요한 작업을 구성하려면 다음 옵션의 라디오 버튼을 선택합니다.
    • 항상 요청서를 다시 엽니다.
    • 종료된 시간부터 일(필요한 일 수 선택) 이내에 동일한 요청서를 다시 엽니다. 그렇지 않으면 새 요청서를 생성합니다.
    • 회신을 대화로 요청서에 추가하고 기술자에게 알립니다.
    • 새 요청서로 생성합니다.

  • 요청자는 다음이 허용됩니다:
    • 프로필 편집: 요청자가 프로필을 수정할 수 있도록 하려면 이 확인란을 선택합니다.
    • 프로필 보기: 요청자가 프로필을 볼 수 있도록 하려면 이 확인란을 선택합니다.

  • 서비스 카탈로그 비용 정보 표시: 서비스 비용을 모든 요청자에게 표시할지 아니면 특정 요청의 승인자에게만 표시할지 구성합니다.
  • 셀프 서비스 포털에서 요청자에게만 연계된 자산 표시 셀프 서비스 포털에서 요청자에게만 자산을 표시하려면 확인란을 활성화할 수 있습니다.
OPTION 'YES' 'NO'
요청자에 대한 기본 요청서 템플릿 비활성화 [기본값은 '아니요'] '예' 라디오 버튼을 활성화하면 요청자가 기본 요청서 템플릿을 볼 수 없습니다. 요청서 템플릿을 모든 요청자가 사용할 수 있습니다.
새 사건 요청서를 생성하는 동안 요청자에게 제안을 표시하시겠습니까? [기본값은 '예'] 요청자에 대해 사건 요청서 생성 중 공지 사항 및 솔루션의 자동 제안이 활성화됩니다. '아니요' 라디오 버튼을 활성화하면, 요청자가 새 사건 요청서를 생성하는 동안 제안을 볼 수 없습니다.
요청서에 대한 상태 변경 의견 필수 [기본값은 '아니요'] '예' 라디오 버튼을 활성화하면 요청서 상태 변경에 대한 의견이 필수가 됩니다.

상태 변경 의견이 요청서에 필수 사항이 아닙니다.

승인 설정:

  • 요청자에게 승인 탭 표시 확인란은 기본적으로 활성화되어 있습니다. 승인 탭은 요청서를 시작한 요청자와 요청서를 승인할 수 있는 요청자에게 표시됩니다. 요청자가 승인 탭을 보지 않도록 하려면 비활성화할 수 있습니다.

  • 승인 요청서 메일 발송할 때애 제한 유형 선택: Admin 관리자는 승인 요청서를 승인할 수 있는 사용자 또는 승인자의 유형을 선택할 수 있습니다. Admin 관리자는 '누구나 승인 가능', '시스템 사용자만 승인 가능', '서비스 요청서 승인자만 승인 가능' 중에서 선택할 수 있습니다.

  • 요청서 자체 승인 허용('자체 승인'에는 요청자, 대리 사용자 및 로그인한 기술자가 포함됩니다. 이 확인란을 선택하면 요청자가 자신의 요청서를 승인할 수 있습니다.. 여기에서 요청자에는 대리 사용자와 로그인한 기술자가 모두 포함됩니다.

  • 요청서 승인을 기다리는 동안 타이머를 중지하고 요청서 상태를 '보류'로 설정은 기본적으로 비활성화되어 있습니다. 확인란을 활성화하면 요청서가 승인을 기다리고 있을 때 타이머가 중지되고 상태가 '보류'로 설정됩니다.
    대부분의 경우 관련 부서에 승인 요청서를 보낼 때 지원 센터 팀에서 승인 프로세스 지연에 대해 책임을 지지 않을 수 있습니다. 헬프 데스크 팀의 SLA 위반을 최소화하기 위해 '승인 대기 중' 상태의 요청서에 대한 타이머를 중지할 수 있습니다. 이 옵션을 사용하려면 확인란을 선택합니다. 드롭다운 상자에서 요청서 상태를 선택할 수도 있습니다.

  • 승인 알림(독촉) 통지 : 일정 기간이 지난 후에도 승인 조치가 수행되지 않는 경우 승인자에게 알리려면 이 옵션을 활성화합니다. 승인 알림(독촉) 통지를 보내는 시간도 구성할 수 있습니다.
    • 알림 통지(독촉) 중지 : 승인자에게 반복적으로 통지되는 알림(독촉)을 중지하려면 이 옵션을 활성화합니다. 승인자에게 보내는 통지 수는 통지 개수를 선택하여 제한할 수 있습니다.
    승인 알림 통지 콘텐츠 사용자 지정: 승인 알림 알림 콘텐츠도 사용자 지정할 수 있습니다. 여기를 클릭하여 메일 콘텐츠를 사용자 지정하십시오.

  • 로그인한 사용자의 승인 작업만 허용 옵션을 '예'로 설정하여 로그인한 승인자만 승인 작업을 수행하도록 허용합니다. 그러나 이 기능이 작동하려면 두 기능이 공존할 수 없으므로 누구나 승인할 수 있음 옵션을 비활성화해야 합니다.

일반 설정:

  • 통화: 주어진 텍스트 필드에 필요한 통화를 지정합니다. 이 단위는 비용 계산이 수행되는 모든 장소에서 사용됩니다. 기본적으로 통화는 미국 달러-USD로 설정됩니다.
  • 통화 기호: 해당 통화의 기호를 표시합니다. 기본적으로 지정된 통화는 $입니다.
  • 기본적으로 애플리케이션을 표시할 언어 선택: 기본적으로 브라우저 기본 언어가 표시됩니다. 애플리케이션은 다양한 언어를 지원하며 사용자는 드롭다운 목록에서 필요한 언어를 선택할 수 있습니다.
  • 요일 시작: 선택한 요일이 모든 캘린더 보기에서 해당 주의 시작 요일로 간주됩니다. 기본적으로 시작 요일은 일요일입니다.
OPTION 'YES' 'NO'
요청서 세부정보 페이지에 사이트 세부정보 표시 ?[기본값은 '예'] 요청서 세부 정보 페이지에서 사이트 이름, 주소 및 연락처 정보와 같은 사이트 세부 정보를 볼 수 있습니다.사이트 세부 정보를 보려면 요청서 세부 정보 페이지의 사이트 매개변수 옆에 사이트 세부 정보 보기 아이콘이 나타납니다. '아니요' 라디오 버튼을 활성화하면 요청서 세부 정보 페이지에서 사이트 세부 정보 보기 아이콘이 제거됩니다.
서비스에 대한 사건 및 서비스 템플릿 목록 결합[기본값은 '예'] 사고 및 서비스 템플릿은 특정 범주에 따라 그룹화되고 새 요청서 드롭다운 메뉴에 나열됩니다. '아니요' 라디오 버튼을 활성화하면 사건 및 서비스 템플릿이 목록에 결합되는 것을 방지할 수 있습니다.
애플리케이션에서 사용자를 가져오지 않을 때 동적 사용자 추가를 허용하시겠습니까?[기본값은 '예'] 사용자를 애플리케이션으로 가져오지 않고 Active Directory를 통해 가져온 경우 사용자는 AD 자격 증명을 사용하여 애플리케이션에 로그인할 수 있습니다. 그러면 애플리케이션에 대한 로그인 액세스가 자동으로 제공됩니다. '아니요' 라디오 버튼을 활성화하면 사용자가 애플리케이션으로 가져오지 않을 때 동적 사용자 추가가 방지됩니다.
이메일 요청을 통해 생성된 사용자에게 로그인 액세스를 제공하시겠습니까?[기본값은 '예'] 처음으로 이메일 요청을 보낼 때, 사용자에게 자동으로 로그인 액세스 권한이 제공됩니다. '아니요' 라디오 버튼이 활성화된 경우 이메일 요청을 통해 생성된 사용자에게는 로그인 액세스가 제공되지 않습니다.
이메일 ID를 기반으로 사용자 정보를 덮어쓰시겠습니까?[기본값은 '예'] Active Directory, CSV 및 LDAP를 사용하여 사용자를 가져올 때, 기존 사용자 정보는 두 가지 기준에 따라 덮어쓰여집니다. 첫 번째 기준은 사용자 이름과 도메인을 기준으로 하고 두 번째 기준은 이메일 ID를 기준으로 합니다. '아니요' 라디오 버튼을 활성화하면 이메일 ID를 기반으로 한 사용자 정보가 기존 정보를 덮어쓰지 않습니다.
사용자가 로컬 인증을 기반으로 로그인하도록 허용하시겠습니까?[기본값은 '예'] 사용자는 로컬 인증을 사용하여 애플리케이션에 로그인할 수 있습니다. '아니요' 라디오 버튼을 활성화하면 사용자가 로컬 인증을 기반으로 로그인할 수 없습니다.
새 이메일 주소에서 수신된 이메일을 처리하시겠습니까?[기본값으로 '예'] 새 이메일 주소의 이메일이 SDP 애플리케이션으로 들어오는 것을 방지할 수 있습니다. '아니요' 라디오 버튼을 활성화하면 새 이메일 주소의 이메일을 처리하 됩니다.
기술자를 위한 '빠른 생성' 섹션을 표시하시겠습니까?[기본값은 '예'] 빠른 생성 섹션이 홈페이지의 기술자에게 표시됩니다. '아니요' 라디오 버튼을 활성화하면 홈페이지의 기술자에게 빠른 생성 섹션이 표시되지 않습니다.
이메일을 통해 생성된 요청서에 대해 요청자 자산을 자동으로 설정하시겠습니까?[기본값은 '예'] 일반적으로 여러 자산을 요청자에 연결할 수 있습니다. 따라서 이메일을 통해 요청을 제기할 때, 기본적으로 요청자와 연계된 첫 번째 자산이 표시됩니다. 이메일을 통해 생성된 요청서에 대해 요청자의 자산이 자동으로 설정됩니다. '아니요' 라디오 버튼을 활성화하면 이메일을 통해 생성된 요청서에 대해 요청자의 자산이 자동으로 연계되지 않습니다.
솔루션 승인자가 자신의 솔루션을 승인할 수 있습니까?[기본값은 '예'] 솔루션 승인자는 승인을 위해 제출하는 대신 자신의 솔루션을 승인할 수 있습니다. '아니요' 라디오 버튼을 활성화하면 솔루션 승인자가 자신의 솔루션을 승인할 수 없습니다.
요청자가 모바일 애플리케이션에 액세스하도록 허용[기본값은 '아니요'] '예' 라디오 버튼을 활성화하면 요청자가 모바일 애플리케이션에 액세스할 수 있습니다. 요청자는 충분한 권한이 제공되지 않는 한 모바일 애플리케이션에 액세스할 수 없습니다.
비로그인 사용자가 솔루션을 볼 수 있도록 허용 '예' 라디오 버튼을 활성화하면 로그인 자격 증명이 없는 사용자가 솔루션을 볼 수 있습니다. '아니요' 라디오 버튼을 활성화하면 로그인 자격 증명이 없는 사용자가 솔루션을 볼 수 없습니다.
로그인 중 도메인 필터링 허용 '예' 라디오 버튼을 활성화하면 도메인 필터링 옵션이 표시됩니다. '아니요' 라디오 버튼을 활성화하면 로그인하는 동안 도메인 필터링 옵션이 숨겨집니다.
  • 외부 세계에 노출될 별칭 URL 구성: 대체 URL 제공
    1. http:// 텍스트 옆에 제공된 텍스트 필드에 URL을 입력합니다(필요한 경우 포트 번호와 함께).예: support.acme.com:8080.
    2. 입력한 URL은 '새 창에서 별칭 URL 열기' 링크를 클릭하면 확인할 수 있습니다.

헤더 이미지 사용자 정의:

  • 사용자 정의 이미지를 사용하여 기본 헤더 이미지를 바꿀 수 있습니다. 이미지 가져오기 >> 파일 선택 >> 가져오기를 클릭하여 맞춤 이미지를 업로드하십시오. 가져온 후, 사용자 지정 이미지 사용 라디오 버튼을 클릭합니다.
  • 헤더 이미지의 크기는 155px x 38px(W x H)
이어야 합니다.

로그인 페이지 사용자 지정:

  • 요구 사항에 따라 애플리케이션 로그인 페이지를 사용자 정의합니다. 배경 이미지를 업로드하거나 스타일을 추가하거나 요구 사항에 맞게 html 파일을 수정할 수도 있습니다.
  • 지금 사용자 정의을 클릭합니다. HTML 편집기가 열립니다.
  • 표시된 편집기에서 필요한 사항을 변경할 수 있습니다.
  • 로그인 로고 이미지는 205px x 61px(W x H) 크기여야 합니다.
  • 설정을 저장하면 변경 사항이 즉시 적용됩니다. 즉, 애플리케이션을 다시 시작할 필요가 없습니다.
  • 변경사항을 모두 취소하려면 오른쪽 상단에 있는 기본값으로 복원 을 클릭하십시오.
