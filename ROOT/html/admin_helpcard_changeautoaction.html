With Custom Trigger, you can automatically trigger the required 'Action' using the script file or custom class file or custom function. In the 'New Action' window, provide the name and description for the new action. From the drop-down list, select the instant at which the action has to be executed. Set the 'Criteria' fields, its corresponding conditions and their field values. Select the 'Action Type' and the corresponding script file or class file or custom function that has to be triggered. Deselecting 'Stop processing subsequent actions' checkbox will execute successive action even after an action rule is applied on a change.

FACTS:

  • Make sure that you enter an unique name for the 'New Action' ,so that the name doesn't clash with existing 'Action' names.
  • Ensure that the script /class file is stored only in the specified locations. Store them in the directory as follows: [SDP_Home]/integration/custom_scripts/
  • By default, 'Stop processing subsequent actions' is always enabled and the actions will be executed as per the 'Action rule order'.
  • 'Organize Actions' allow you to rearrange the order in which the actions are executed.

SAMPLE SCENARIO:

When an Emergency Change Request is raised, an emergency CAB need to be configured so as to verify and approve the Change Request immediately. Here a new action can be configured to execute a Custom Script or Custom Function when an Emergency Change Request is raised.

TECHNICAL DETAILS:

Under Perform Action, choose whether you want to execute class, script, or custom function and configure the same using the following pointers:

  • Class: Specify the Executor class. For example, com.servicedeskplus.integration.ChangeActionImplementation. 
  • Script: Specify the name of the text file containing the script execution content. For example, AddApprovers.txt.
  • Custom Function: By executing custom functions, you can manipulate data in ServiceDesk Plus and other external applications. Choose the required custom function or add a new one. changeObj and context are the arguments supported in custom functions.

Note::

  1. In a script or a class, you can pass all API parameters as arguments, such as py addApprovers.py $TITLE $TYPE $TEMPLATE. In a class you could pass com.servicedeskplus.integration.ChangeActionImplementation $TITLE $TYPE $TEMPLATE.
  2. changeObj and context are the arguments supported in custom functions.

Other Parameters Supported in Script:

$COMPLETE_V3_JSON_FILE ---> Complete Request Object will be saved to a JSON file and the file path will be passed as String Object. If the Operation is 'When a Change is edited', then DIFF_JSON (difference between the old change data and new change data) will also be saved to a JSON file.

$HELPDESK_ID ---> The ID of the portal. This id needs to be passed as the value to all SDP API calls, against new URL parameter 'PORTALID'. This is applicable only for ESM enabled setups.

JSON File Path  : (SDP_Home\integration\custom_scripts\change\12_1426143538036.json).

Input data for trigger application:

{
INPUT_DATA :
{

"entity" : "module name: here change",
"entity_diff_data" : "difference between the old change data and new change data",

}
